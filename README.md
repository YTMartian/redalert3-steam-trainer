# 红警3 Steam 版进程内菜单

《命令与征服：红色警戒3》Steam 1.12 的进程内菜单。DLL 注入游戏逻辑进程 `ra3_1.12.game`，用 ImGui 改 MustCode、FLAGS 和单位内存。不改游戏目录里的文件。

- 游戏版本：**Steam 1.12**（进程模块 `ra3_1.12.game`）
- 形态：Win32 (x86) DLL `overlay\bin\ra3_overlay_v4.dll`，挂在 D3D9 的 Present 上绘制
- 注入：`overlay\bin\main.exe` 把 DLL 载入游戏；菜单里的「注入」再装配 MustCode
- 语言：菜单为简体中文

> **仅供单机 / 遭遇战娱乐与逆向学习。** 不要在线上对战使用。
> 仓库不含游戏本体。

编译步骤、目录和排错补充见 [overlay/README.md](overlay/README.md)。

## 快速开始

1. Steam 库 → 右键《红色警戒3》→ 属性 → 启动选项，填 `-runver 1.12`。建议窗口化进入遭遇战。
2. 进局后，**以管理员身份**运行 `overlay\bin\main.exe`。弹窗标题就是结果：**注入成功** 或 **注入失败**；失败时正文写原因（没找到游戏、没有管理员权限、DLL 没载入）。如果游戏不是用 1.12 启动的（例如正在跑 `ra3_1.13.game`），注入会失败，并弹出两张图：Steam 里右键游戏打开「属性」，启动选项填 `-runver 1.12`，然后完全退出再重新进游戏。若 `Ra3.BattleNet.Client.exe` 或 `RA3BattleNet.exe` 正在运行（安装目录不限），修改器不会启动，提示「请关闭战网进程（RA3BattleNet）」。
3. 游戏内按 **Home**（或 Insert / F8）打开菜单。观战开局先勾选 **「观战模式」**，再点 **「注入」**。

改过 DLL 之后必须重新注入。游戏里仍是上一次注入的那份。

日志在注入器同目录：`overlay\bin\ra3_overlay.log`。普通记录和崩溃堆栈都写在这里，每次重新注入会先清空。DLL 路径解析失败时才会退到系统临时目录。

发给别的玩家时，只拷贝 `overlay\bin\main.exe` 即可。第一次运行会在这个 exe 旁边释出 `ra3_overlay_v4.dll`、`arm_mustcode.dll` 和 `unit_names_csf.txt`。`arm_mustcode.dll` 仍是装配程序，只是扩展名改成 dll，避免和 `main.exe` 点错。已有的 `unit_names.txt` 不会被盖掉。单位图标在 DLL 内部，不再写出 `unit_images` 文件夹。界面、热键和日志写在 exe 旁边（`overlay_ui.ini`、`ra3_overlay.log`）。v1.12 引导图留在注入器内部。本机如果还留着仓库根目录的旧界面文件，下次注入会把它复制到 DLL 旁边。

### 界面约定

窗口默认约 900×720，左侧分类，右侧功能页。

| 控件 | 怎么用 |
|------|--------|
| 开关 | 资源、超武/地图、单位操作里一行三个。点名称或开关 |
| 危险等级 | 与名称同一行的三段：正常 / 高 / 最高 |
| 己方资金 | 「+」「-」。点名称可改每次金额，默认 10 万。热键只加、不减 |
| 选中玩家资金、出场等级、召唤基地车、召唤部队 | 整行：先点玩家（颜色方块 + 阵营名），再操作 |
| 一次性操作 | **执行**。复制、摧毁、召唤等在后台做，避免卡住画面 |
| 热键 | 功能名旁的齿轮，可改键。悬停能看到当前热键 |

四项玩家选择互不影响：资金、出场等级、召唤基地车、召唤部队各记各的。只列出已经进局的玩家；己方标「己方」，被击败的标「已击败」。

菜单最下方有选中单位检查：选中后显示实体指针、血量、速度、星级。

**界面设置**里可以调缩放（0.70–1.30，默认 1.00）和背景透明度（35%–100%，默认 80%）。

### 观战模式

勾选「观战模式」再点「注入」时，不装这 5 个资源 hook：PlayerID、Money、Power、SCPoint、HaveAllSC。电力无限、科技点无限、全科技在观战下不可用，用来避免进局闪退。速度、血量、满级、摧毁、复制、召唤基地车、召唤部队仍可用。复制时若没有本地玩家归属，会提示失败。钩子在点「注入」后立刻装上。

载入存档时游戏内存池偶尔扩容失败，原逻辑不判断空指针，会去读 `0xFFFFFFFC` 然后退出。菜单在分配器返回空时改从进程堆补一块同样布局的内存，加载可以继续。日志里若出现 `pool returned null` 就是走了这条补救。

没有单独的观战页。

## 一、功能列表

侧栏：资源、超武/地图、弹药/危险、单位操作，以及建造限制、战况统计、界面设置。

### 资源

| 功能 | 说明 |
|------|------|
| 选中玩家资金 | 点选战场上的玩家后加减该玩家的钱。默认每次 1 万，可改步长。热键只加这一档 |
| 己方资金 | 加减自己的钱，直接写资金对象。默认每次 10 万。热键 Ctrl+F1 只加 |
| 电力无限 | 电力锁定。热键 Ctrl+F2 |
| 科技点无限 | 科技点锁定。热键 Ctrl+F3 |
| 全科技 | 解锁全部科技。热键 Ctrl+F4 |
| 快速建造 | 建筑和单位的建造速度提升。热键 Ctrl+F5 |
| 恢复矿场 | 一次性恢复矿场。热键 `'` |

观战模式不装金钱 / 电力 / 科技点 / 全科技这几处 hook，对应开关不会生效。己方资金和选中玩家资金走的是直接改玩家资金，不依赖那几个 hook。

### 超武 / 地图

| 功能 | 说明 |
|------|------|
| 超级武器 | 超级武器无冷却。热键 Ctrl+F6 |
| 禁用超武 | 拖住敌方超级武器冷却（己方单位技能和协议不受影响；敌方单位技能可能一并被拖）。打开时还会把六座超级武器建筑加入建造限制。读档或战局还没跑起来时先不改冷却、也不调用游戏的建造限制，等场上出现单位约 2 秒（空场则等战局时钟走动约 12 秒）再生效，避免读档时把空的生产队列扩容写崩。开关本身会一直保持勾选。热键 Ctrl+F7 |
| 消散战争迷雾 | 打开后马上清掉整张地图的战争迷雾，高地和还没探索的地方也一起清掉，不用再造建筑或走动。关掉或卸载后按原来的探索结果恢复。热键 Ctrl+F9 |
| 敌人无法建造 | 敌方无法建造。热键 Ctrl+F10 |
| 协议无冷却 | 开关。打开后一直清掉己方协议冷却，关掉恢复。和「单位技能无冷却」「超级武器」共用同一处 hook，其中任一开着，冷却就一直被清掉 |
| 单位技能无冷却 | 开关。打开后一直清掉己方单位技能冷却，关掉恢复。和协议无冷却是同一处 hook |
| 禁用敌方协议 | 开关。打开后一直拖住敌方协议冷却，关掉恢复。不会像「禁用超武」那样把超级武器建筑加入建造限制 |

要单独禁止某一座超级武器，用建造限制里的图标，不要开「禁用超武」。

### 弹药 / 危险

| 功能 | 说明 |
|------|------|
| 弹药无限 | 弹药不减少。热键 `;` |
| 危险等级 | 与名称同一行：正常 / 高 / 最高。热键 `/` 正常，`,` 高，`.` 最高 |

### 单位操作

本组默认要先在游戏里选中单位。出场等级、召唤基地车和召唤部队不用选单位，它们用自己的玩家列表。

| 功能 | 说明 |
|------|------|
| 超速 ×500 / 慢速 ×10 / 冻结 / 恢复速度 | 改选中单位速度。热键 `-` / `=` / PageUp / PageDown |
| 无敌 / 残血(1点) / 恢复血量 | 改选中单位血量。热键 `[` / `]` / `\` |
| 满级(3星) | 在独立线程里调官方加经验接口 `0x5173F0`，循环到该单位等级不再上升。星星、加成和 EVA 由引擎自己处理。热键 `P` |
| 摧毁选中 | 调官方摧毁接口 `0x7DCDF0`。热键 Delete |
| 复制选中 | `CreateUnit`（`0x6440F0`）在鼠标地图落点生成。正常归己方，观战归原阵营。鼠标要在地形上。热键 `I` |
| 复制到己方 | 同上，归属强制本地玩家 |
| 批量复制 | 每个选中模板在鼠标附近各复制 5 份 |
| 收编敌方 | 把选中单位的归属改成本地玩家 |
| 一键满状态 | 满血，短暂打开弹药无限约 0.3 秒，再尽量满星 |
| 伤害×5 | 写星级加成倍率（`sub+0x08`）。单位之后再升星时，引擎可能按倍率表重算 |
| 出场等级 | 选玩家后拖动 0–3。0 为不设置；1–3 只影响该玩家之后生产出来的单位，不改已经在场上的 |
| 召唤基地车 | 选玩家，再点盟军 / 苏联 / 帝国基地车图标，在鼠标所在地形召唤一辆，归该玩家 |
| 召唤部队 | 选玩家，点三家部队图标加入上方候选框（再点候选图标可拿掉；不含建筑）。三家下面另有「特殊单位」，目前是磁暴坦克。每种数量默认 1，围着鼠标散开，归所选玩家。生成排到游戏绘制那一帧，不和单位更新抢同一时刻。热键 `U`，用当前玩家、兵种和数量；按钮旁只留齿轮，不写键名 |

## 三、战况统计

侧栏打开 **战况统计**。只列出已经进局的玩家：观战席、空座位和中立席不显示。被击败的玩家仍留在榜上，名字旁标「已击败」，折线和累计金额保留，场上数量归零。

- 标题是一颗**玩家颜色色块**加上阵营（盟军 / 苏联 / 帝国），己方后面另标「己方」。观战注入时标题旁有「观战」。
- 卡片上有当前资金、电力，以及场上还活着的部队、建筑（图标 + 数量）。攻击无人机、卫星扫射和帝国点防御无人机不进这张表。
- **协议**单独一行，图标加数量。悬停可看名称：冷却中显示剩余秒数，否则显示就绪。精简视图同样有这一行。
- 纳米核心展开成建筑后，统计里不再留着已经失效的核心（例如超能波毁灭装置建好后的「毁灭装置核心」）。纳米虫群显示为「纳米虫群巢穴」。
- **本局**是一张折线图，五条线：建造、损失、消灭（部队和建筑加在一起），以及收入、支出。数量和金额各自按自己的最大值缩放，避免金额把前三条线压扁。鼠标悬停可看该时刻的时间、部队与建筑的拆分，以及收入、支出金额。
- 横轴从战局 **0:00** 画到现在。游戏记分板和存档只保存累计总数（ScoreKeeper：收入、支出、建造、损失、消灭），不保存逐秒曲线。开始记录之前的那一段，是从开局的 0 连到当时的官方累计值，之后按实际采样画。右端始终是当前的完整统计。
- 采样大约每秒一次；数值没变时会把点抽稀。超过约 1800 个点后保留起点、隔点保留中间、并保留最新一点。
- 「固定」默认关闭。不固定时，关掉主菜单会一起关掉战况窗口；勾上固定后，Home 只关主菜单。每次重新注入都会回到不固定。
- 「精简」不画折线。每个玩家第一行是名字，资金和电力写在同一行并标明。下面部队一行、建筑一行，用图标和数量。勾选会记在 `overlay_ui.ini` 里。

图标编进 DLL。源图仍放在仓库根目录的 `unit_images\`，`build.bat` 打包时读它。文件名用游戏/Wiki 中文名（不含 `.png`），按阵营分子目录：

```
unit_images/
  盟军/{单位,建筑,协议}/
  苏联/{单位,建筑,协议}/
  帝国/{单位,建筑,协议}/
  中立单位建筑/     # 医院、车库、船坞、机库、油井、桥梁、矿脉等科技建筑
  战役建筑/         # 战役关卡建筑（杰斐逊、克里姆林宫、自由女神像等）
  特殊单位/         # 天空骑士、磁暴坦克等
```

协议目录里的 `.webp` 在打包时转成 PNG 再编进 DLL。中立与战役建筑图标来自 [红警3 BWiki · 中立&战役建筑](https://wiki.biligame.com/redalert3/%E4%B8%AD%E7%AB%8B%26%E6%88%98%E5%BD%B9%E5%BB%BA%E7%AD%91)。叠加层按 PNG 文件名匹配场上单位显示名。界面上的种类名会转成简体；`unit_names.txt` 里的手写名优先。

新出现的种类追加在列表末尾，不会插进已有图标中间。

## 四、建造限制

侧栏 **建造限制**。上下两栏：上面是允许建造，下面是禁止建造。每栏按盟军、苏联、帝国分开展示图标，悬停显示名称。点允许栏里的图标即禁止，点禁止栏里的图标即恢复。

- 对当前对局里所有非中立玩家生效，包括 AI。名单会记住，进入下一局后自动再套一次，直到你手动解禁。
- 进局后会等战局时钟连续有效约 3 秒，才把禁止写进游戏。加载存档的那几秒里不去调游戏的建造接口，避免分配失败后读空指针。
- 车厂和船厂都能造的单位只显示一个图标（MCV、勘探者、激流 ACV、史普尼克勘察车、牛蛙载具、海啸坦克、采矿车 / 苏联矿车）。禁止后两边都不能造。
- 帝国纳米核心显示成展开后的建筑名和图标。统计面板仍用原来的种类名，避免和统计对不上。
- 不收录开局就有的建造工厂，以及磁暴坦克、雷达碟、斩首中队、气球炸弹、点防御无人机、盟军前哨站、苏联战斗碉堡。
- 点某一座超级武器只限制这一座（纳米虫群核心会连同巢穴，超能波毁灭装置会连同它的核心）。开关「禁用超武」会把六座一起禁止：超时空传送仪、质子撞击炮、铁幕装置、真空内爆弹、纳米虫群核心、超能波毁灭装置。

## 五、单位中文名

游戏用 `Name:<TypeId>` 查语言包。从本机 RA3 导出官方表：

```
python overlay\tools\extract_csf_names.py --ra3 "你的RA3安装目录"
```

生成 `overlay\bin\unit_names_csf.txt`。注入器会把它和图标一起释到 exe 旁边。手动覆盖写在同目录 `unit_names.txt`，优先于 CSF，重新运行注入器不会盖掉这份手改文件。

## 六、技术原理

### 进程

`RA3.exe` 是启动器。真正的引擎是 `Data\ra3_1.12.game`。主模块无 ASLR，镜像基址 `0x400000`。`.text` / `.rdata` / `.data` 的文件偏移等于 RVA。

菜单画在 `Present` 上。`EndScene` 的钩子不负责画界面。渲染包在 SEH 里，避免一次绘制异常把游戏带走。

### MustCode

点「注入」后，DLL 调用同目录的 `arm_mustcode.dll`（内容仍是装配程序，扩展名做成 dll，避免和 `main.exe` 点错；内含 `keystone.dll`，用 `mustcode_asm.py` 装配），在游戏进程里分配几块内存并打 5 字节 `jmp`：

| 段 | 用途 |
|----|------|
| MustCode | 主要 hook 逻辑 |
| MustCode2 | 单位速度 / 血量 |
| FLAGS | 各功能开关，一字节一个 |
| IDB | 单位数据基址缓存 |

`.text` 默认只读，写补丁前会改页保护，写完再恢复。观战模式跳过 PlayerID、Money、Power、SCPoint、HaveAllSC。

17 个 hook（Steam 1.12 VA）：

| Hook | VA | 功能 |
|------|-----|------|
| PlayerID | `0x54119B` | 玩家 ID |
| Money | `0xA64E9E` | 金钱 |
| Power | `0xA64DAD` | 电力 |
| SCPoint | `0xA64F0C` | 科技点 |
| HaveAllSC | `0xA64F55` | 全科技 |
| FastBuild1 | `0x74D81E` | 快速建造 |
| FastBuild2 | `0x74D77C` | 快速建造 |
| FastBuild3 | `0x73511F` | 快速建造 |
| SuperPower | `0x729F19` | 超级武器 |
| SuperPower2 | `0x87CB89` | 超级武器 |
| DisableAllSP | `0x87CC16` | 禁用敌方超武 |
| DisableAllSP2 | `0x748A06` | 禁用敌方超武 |
| Map | `0x8005BC` | 消散战争迷雾 |
| UnitAmmo | `0x569D85` | 弹药无限 |
| DangerLevel | `0x877070` | 危险等级 |
| OreMine | `0x712EB3` | 恢复矿场 |
| EnemyCantBuild | `0x74D920` | 敌人无法建造 |

写入前会核对原始字节。对不上就报 probe failed：多半不是 1.12，或别的修改器已经改过这些位置。

### 选中单位

速度、血量、摧毁、复制都从选中单位管理器出发：

```
[模块 + 0x8E08DC] = 管理器          绝对地址 0xCE08DC
管理器 +0x5C      = 当前选中数量
管理器 +0x50      = 选中链表头
  节点 +8         → 对象
  对象 +0x138     → 单位实体
  实体 +0x374     → 单位数据（+0x200 速度 / +0x33C 血量）
  实体 +0x3CC     → 经验追踪器
  实体 +0x418     → 归属玩家
```

`0x8E08DC` 是 RVA。函数地址（例如 `0x5173F0`、`0x6440F0`）是已经含基址的 VA。两者不能混用：把 RVA 再按 VA 去减 `0x400000`，会少整整一个基址，读到空列表。

Steam 版是重编译的二进制，零售版全局指针 `0x8DB73C` 在这份模块里没有引用。对象内部偏移 `+0x50 / +0x5C / +0x138` 没变。

### 玩家

玩家列表全局 RVA `0x8EDE2C`：

| 偏移 | 含义 |
|------|------|
| `+0x28` | 本地玩家 |
| `+0x2C` | 数量 |
| `+0x30` | `Player*[0x14]` |
| 玩家 `+0x14` | 显示名 |
| 玩家 `+0x20` | player_id，0 为中立 |
| 玩家 `+0x80 / +0x84` | 颜色 ARGB |
| 玩家 `+0xE4` | 资金 |
| 玩家 `+0x74` | 电力 |
| 玩家 `+0x1F0` | ScoreKeeper（累计，不是时间序列） |

资金加减写资金对象 `+0x04`，范围夹在 0 到 2 亿。

### 满级为什么不在 hook 里调用游戏

`0x5173F0(entity, xp)` 是官方「给单位加经验」入口，内部会进 `ExperienceTrackerObject::SetRank`，由引擎自己派发晋升、EVA 和星星。直接写 `tracker+0x24` 只改缓存，游戏里的星级不变。

这个接口不能在 MustCode hook 里同步调用。玩家更新那条 hook 的调用者已经拿着全局锁 `0xCDDF20`，而加经验一进来又要加同一把非递归锁，会自死锁，游戏画面停住。现有 17 个 hook 都只做内存读写。满级、摧毁、复制、召唤基地车都放到独立线程里再 `call` 游戏函数。

经验追踪器（虚表邻近字符串 `ExperienceTrackerObject`）：

| 偏移 | 含义 |
|------|------|
| `+0x08` | 当前等级的定义键 |
| `+0x0C` | 当前经验（float） |
| `+0x10` | 下一级所需经验 |
| `+0x1C` | 经验倍率 |
| `+0x20` | 最低字节是「等级特效已播放」 |
| `+0x24` | 等级索引缓存，实测约 0–4。写入它不会让星星变化 |
| `+0x2C` | 加成对象 `sub` |
| `sub+0x08` | 当前加成倍率。伤害×5 写的是这里 |

### 出场等级和召唤

出场等级走生产老兵升级：`Upgrade_ProductionVeterancy_VETERAN / _ELITE / _HEROIC`，对应滑条 1 / 2 / 3。查找升级 `0x586CF0`，授予 `Player::setUpgrade` `0x88B800`，清除 `0x888510`。这是累加的，只影响之后生产的单位。

召唤基地车用 `CreateUnit` `0x6440F0`。模板从 Thing 工厂 RVA `0x008EBDE8` 按 `AlliedMCV` / `SovietMCV` / `JapanMCV` 查找，归属是基地车那一栏选中的玩家，落点是鼠标投影到地形的坐标。

### 加载战局时不要在游戏线程里分配

CreateUnit / SpawnObject / Destroy 的钩子只把指针放进固定数组，分类和建表放到界面线程。重扫单位表会等约 2.5 秒。建造限制要等战局时钟有效满 3 秒。加载存档时游戏自己的分配器可能返回空，紧接着读 `[NULL-4]`；如果钩子在同一条游戏线程上做堆分配，就会撞上这次崩溃。

崩溃日志记异常码、EBP 回溯，以及栈上能认出的模块偏移，写在 `ra3_overlay.log`。

### 换模式时的空指针

遭遇战结束后，玩家列表全局有时还指着已经释放的内存。脚本按座位取玩家时，读不到就当成没有这个玩家，继续往下走，不会把整张玩家表换成别的对象。AI 选择超武时，查找结果为空就跳过这一次。这两处在 DLL 载入时就装上。日志里应有 `ai power null guard`、`script player guard` 和 `player slot guard sites=2`。

### 存档里没有折线

遭遇战存档在「保存的游戏」目录下，例如：

```
C:\Users\<用户>\Saved Games\Red Alert 3\<档案号>\<名字>.RA3Skirmish
```

档案号来自 `%AppData%\Roaming\Red Alert 3\Profiles\directory.ini` 的 `CurrentProfile`。游戏用 `FOLDERID_SavedGames` 拼出这条路径。存档是 RGMH 头加 BLOK 块的快照（玩家、GameLogic、地图状态），里面没有逐秒统计。所以折线在开始记录之前只能从 0 直线连到当时的累计值。

## 七、编译

### 菜单 DLL

需要 VS Build Tools（x86）和 CMake：

```bat
cd overlay
build.bat
```

输出 `overlay\bin\ra3_overlay_v4.dll`。编完后重新运行注入器。

### 注入器

需要 Python、PyInstaller 和 keystone-engine：

```bat
cd overlay
build_injector.bat
```

先编好 DLL（`build.bat`），再编注入器。注入器会把当时的 DLL、`arm_mustcode.dll`、名字表和图标打进去。

输出：

- `overlay\bin\main.exe`（管理员权限，发给别人只需要这一个文件）
- `overlay\bin\arm_mustcode.dll`（装配程序，扩展名是 dll，避免被当成要双击的程序；玩家那边由注入器自己释出）

若改过 `mustcode_body.asm` / `payload.py`，先在仓库根目录：

```bat
python gen_payload.py
```

Windows 安全中心有时会把注入器隔离。这是附加进程、写内存时的启发式误报。在「病毒和威胁防护 → 排除项」里加上本仓库目录或 `overlay\bin`，再从防护历史里还原文件。

## 八、排错

| 现象 | 可能原因 |
|------|----------|
| 注入弹窗写「注入失败」 | 先看正文：游戏没开、没管理员权限，或 DLL 被安全软件隔离 |
| 请关闭战网进程（RA3BattleNet） | 在线客户端还在运行。关掉 `Ra3.BattleNet.Client.exe` 和 `RA3BattleNet.exe` 后再开修改器 |
| 弹出两张 Steam 截图 | 当前进程不是 `ra3_1.12.game`。按图在启动选项填 `-runver 1.12` 后重开游戏 |
| 注入失败 / probe failed | 不是 1.12，或已有其它 MustCode 改写了对应字节 |
| 开关无效 | 未点「注入」；观战模式没装资源 hook，电力 / 科技点 / 全科技不会动 |
| 菜单「注入」失败找不到 arm | 注入器没把 `arm_mustcode.dll` 释到 DLL 旁边。重新运行注入器；若安全软件隔离了释出的文件，把该目录加进排除项 |
| arm 报 keystone 动态库失败 | 重新跑 `build_injector.bat`（需打包 `keystone.dll`） |
| 复制失败 | 鼠标不在地形上；先选中单位；观战时没有本地玩家归属 |
| 选中玩家资金没反应 | 还没进局，或列表里没点过玩家 |
| 菜单不出现 | Steam Overlay 冲突；看 log 是否有 `hooked Present` |
| 旧 DLL 占文件锁 | 关掉游戏后重编；输出名为 `ra3_overlay_v4.dll` |
| 加载战局后崩溃 | 看 `overlay\bin\ra3_overlay.log` 里的异常码和模块偏移，确认注入的是当前这份 DLL |
| 退出遭遇战，或接着进任务时崩溃 | 完全退出游戏后重新运行注入器。日志应有 `player slot guard sites=2`；若仍是 `player list read guard sites=7`，说明还在用上一份 DLL |

只支持 Steam 1.12。其它版本的基址和原始字节对不上，注入会在 probe 处停住。
