# 红警3 Steam 版进程内菜单

《命令与征服：红色警戒3》的进程内菜单，同时支持 **原版 Steam 1.12** 和 **起义时刻 1.0**。DLL 注入游戏逻辑进程，用 ImGui 改 MustCode、FLAGS 和单位内存。不改游戏目录里的文件。

- 游戏版本：**Steam 原版 1.12**（进程模块 `ra3_1.12.game`）与 **起义时刻 1.0**（进程模块 `ra3ep1_1.0.game`）
- 形态：Win32 (x86) DLL `overlay\bin\ra3_overlay_v4.dll`，挂在 D3D9 的 Present 上绘制
- 注入：`overlay\bin\main.exe` 把 DLL 载入游戏；菜单里的「注入」再装配 MustCode
- 语言：菜单为简体中文

两个游戏各有一套 hook 表（地址、原始字节、字段偏移都不同），运行时按已加载的模块名自动切换：`ra3_1.12.game` 走原版表，`ra3ep1_1.0.game` 走起义时刻表，互不影响。原版功能不因支持起义时刻而改动。

摄像机、时间控制、动画 / Lua、杂项操作这四个面板，以及单位操作扩展（选择范围 / 切换队伍 / 禁用鼠标输入），对应的是另一个视频拍摄插件 **CameraBridgeRelease** 的功能，目前只适配原版 Steam 1.12；在起义时刻下这些面板会显示「未就绪 / 暂未适配」并置灰，不会静默失败。

> **仅供单机 / 遭遇战娱乐与逆向学习。** 不要在线上对战使用。
> 仓库不含游戏本体。

编译步骤、目录和排错补充见 [overlay/README.md](overlay/README.md)。

## 快速开始

1. Steam 库 → 右键游戏 → 属性 → 启动选项：**原版**填 `-runver 1.12`，**起义时刻**填 `-runver 1.0`（两个游戏各自的启动选项）。建议窗口化进入遭遇战。
2. 进局后运行 `overlay\bin\main.exe`。弹窗标题就是结果：**注入成功** 或 **注入失败**；失败时正文写原因（没找到游戏、没有管理员权限、DLL 没载入）。如果运行的版本不对（原版不是 `ra3_1.12.game`，或起义时刻不是 `ra3ep1_1.0.game`），注入会失败，并按对应游戏弹出两张 Steam 属性的截图：在启动选项里填对应的 `-runver`，然后完全退出再重新进游戏。若 `Ra3.BattleNet.Client.exe` 或 `RA3BattleNet.exe` 正在运行（安装目录不限），修改器不会启动，提示「请关闭战网进程（RA3BattleNet）」。
3. 游戏内按 **Home**（或 Insert / F8）打开菜单。观战开局先勾选 **「观战模式」**，再点 **「注入」**。

改过 DLL 之后必须重新注入。游戏里仍是上一次注入的那份。

日志在注入器同目录：`overlay\bin\ra3_overlay.log`。每次重新注入会把上一份改名为 `ra3_overlay.log.prev`（不再直接删掉，崩溃现场往往就在上一份里），新记录写新文件。崩溃堆栈另写 `ra3_overlay.log.crash`，这个文件**从不删除**，跨会话累加。DLL 路径解析失败时才会退到系统临时目录。

发给别的玩家时，只拷贝 `overlay\bin\main.exe` 即可。第一次运行会在这个 exe 旁边释出 `ra3_overlay_v4.dll` 和 `arm_mustcode.dll`。`arm_mustcode.dll` 仍是装配程序，只是扩展名改成 dll，避免和 `main.exe` 点错。单位图标和两份种类名表（`unit_names_csf.txt`、`unit_names.txt`）都编进 DLL 内部，不再写出任何数据文件；游戏内改的单位名保存在 `%LOCALAPPDATA%\RA3Overlay\unit_names.txt`。旧版遗留在 exe 旁边的 `unit_names*.txt` 会被自动迁移并删除（手改名不会丢）。界面、热键和日志写在 exe 旁边（`overlay_ui.ini`、`ra3_overlay.log`），摄像机配置写在 `ra3_camera.ini`（同一个目录）。原版和起义时刻的版本引导图都留在注入器内部。本机如果还留着仓库根目录的旧界面文件，下次注入会把它复制到 DLL 旁边。

### 界面约定

窗口默认约 900×720，左侧分类，右侧功能页。

| 控件 | 怎么用 |
|------|--------|
| 开关 | 资源、超武/地图、单位操作里一行三个。点名称或开关 |
| 危险等级 | 与名称同一行的三段：正常 / 高 / 最高 |
| 己方资金 | 「+」「-」。点名称可改每次金额，默认 10 万。热键只加、不减 |
| 选中玩家资金、出场等级、召唤基地车、召唤部队 | 整行：先点玩家（颜色方块 + 阵营名），再操作 |
| 一次性操作 | **执行**。复制、摧毁、召唤等在后台做，避免卡住画面 |
| 热键 | 功能名旁的齿轮，可改键。悬停能看到当前热键 |

四项玩家选择互不影响：资金、出场等级、召唤基地车、召唤部队各记各的。只列出已经进局的玩家；己方标「己方」，被击败的标「已击败」。

菜单最下方有选中单位检查：选中后显示实体指针、血量、速度、星级。

**界面设置**里可以调缩放（0.70–1.30，默认 1.00）和背景透明度（35%–100%，默认 80%）。标题栏旁有「调试」开关（**默认关**）：开启后才在下方固定高度的信息框里显示底层状态；诊断日志只写 `ra3_overlay.log`，不再撑开主窗口造成跳动。

### 观战模式

勾选「观战模式」再点「注入」时，不装这 5 个资源 hook：PlayerID、Money、Power、SCPoint、HaveAllSC。电力无限、科技点无限、全科技在观战下不可用，用来避免进局闪退。速度、血量、满级、摧毁、复制、召唤基地车、召唤部队仍可用。复制时若没有本地玩家归属，会提示失败。钩子在点「注入」后立刻装上。

载入存档时游戏内存池偶尔扩容失败，原逻辑不判断空指针，会去读 `0xFFFFFFFC` 然后退出。菜单在分配器返回空时改从进程堆补一块同样布局的内存，加载可以继续。日志里若出现 `pool returned null` 就是走了这条补救。

没有单独的观战页。

## 一、功能列表

侧栏：资源、超武/地图、弹药/危险、单位操作，以及建造限制、协议限制、战况统计、摄像机、时间控制、动画 / Lua、杂项操作、界面设置。

### 资源

| 功能 | 说明 |
|------|------|
| 选中玩家资金 | 点选战场上的玩家后加减该玩家的钱。默认每次 1 万，可改步长。热键只加这一档 |
| 己方资金 | 加减自己的钱，直接写资金对象。默认每次 10 万。热键 Ctrl+F1 只加 |
| 电力无限 | 电力锁定。热键 Ctrl+F2 |
| 科技点无限 | 科技点锁定。热键 Ctrl+F3 |
| 全科技 | 解锁全部科技。热键 Ctrl+F4 |
| 快速建造 | 建筑和单位的建造速度提升。热键 Ctrl+F5 |
| 恢复矿场 | 一次性恢复矿场。热键 `'` |

### 超武 / 地图

| 功能 | 说明 |
|------|------|
| 超级武器 | 超级武器无冷却。热键 Ctrl+F6 |
| 禁用超武 | 拖住敌方超级武器冷却（己方单位技能和协议不受影响；敌方单位技能可能一并被拖）。打开时还会把六座超级武器建筑加入建造限制。读档或战局还没跑起来时先不改冷却、也不调用游戏的建造限制，等场上出现单位约 2 秒（空场则等战局时钟走动约 12 秒）再生效，避免读档时把空的生产队列扩容写崩。开关本身会一直保持勾选。热键 Ctrl+F7 |
| 消散战争迷雾 | 打开后马上清掉整张地图的战争迷雾，高地和还没探索的地方也一起清掉，不用再造建筑或走动。关掉或卸载后按原来的探索结果恢复。热键 Ctrl+F9 |
| 敌人无法建造 | 敌方无法建造。热键 Ctrl+F10 |
| 协议无冷却 | 开关。打开后一直清掉己方协议冷却，关掉恢复。和「单位技能无冷却」「超级武器」共用同一处 hook，其中任一开着，冷却就一直被清掉 |
| 单位技能无冷却 | 开关。打开后一直清掉己方单位技能冷却，关掉恢复。和协议无冷却是同一处 hook |
| 禁用敌方协议 | 开关。打开后一直拖住敌方协议冷却，关掉恢复。不会像「禁用超武」那样把超级武器建筑加入建造限制 |

要单独禁止某一座超级武器，用建造限制里的图标，不要开「禁用超武」。

### 弹药无限 / 危险等级（已并入「单位操作」）

| 功能 | 说明 |
|------|------|
| 弹药无限 | 弹药不减少。热键 `;` |
| 危险等级 | 与名称同一行：正常 / 高 / 最高。热键 `/` 正常，`,` 高，`.` 最高 |

### 单位操作

本组默认要先在游戏里选中单位。出场等级、召唤基地车和召唤部队不用选单位，它们用自己的玩家列表。

| 功能 | 说明 |
|------|------|
| 超速 ×500 / 慢速 ×10 / 冻结 / 恢复速度 | 改选中单位速度。热键 `-` / `=` / PageUp / PageDown |
| 无敌 / 残血(1点) / 恢复血量 | 改选中单位血量。热键 `[` / `]` / `\`。无敌是**累加**的：给一个单位按 `[` 后，再选中另一个按 `[`，前一个继续锁血、新的加进名单；对同一批已锁的单位再按一次才解除这一批。「解除无敌」按钮则清空整个名单。「残血(1点)」在无敌状态下也能直接生效：按 `]` 会先把选中的单位从锁血名单里摘掉，再写 1 点血，不用先解除无敌 |
| 满级(3星) | 在独立线程里调官方加经验接口 `0x5173F0`，循环到该单位等级不再上升。星星、加成和 EVA 由引擎自己处理。热键 `P` |
| 摧毁选中 | 调官方摧毁接口 `0x7DCDF0`。热键 Delete |
| 复制选中 | `CreateUnit`（`0x6440F0`）在鼠标地图落点生成。正常归己方，观战归原阵营。鼠标要在地形上。热键 `I` |
| 复制到己方 | 同上，归属强制本地玩家 |
| 批量复制 | 每个选中模板在鼠标附近各复制 5 份 |
| 收编敌方 | 把选中单位的归属改成本地玩家 |
| 一键满状态 | 满血，短暂打开弹药无限约 0.3 秒，再尽量满星 |
| 伤害×5 | 写星级加成倍率（`sub+0x08`）。单位之后再升星时，引擎可能按倍率表重算 |
| 出场等级 | 选玩家后拖动 0–3。0 为不设置；1–3 只影响该玩家之后生产出来的单位，不改已经在场上的 |
| 召唤基地车 | 选玩家，再点盟军 / 苏联 / 帝国基地车图标，在鼠标所在地形召唤一辆，归该玩家 |
| 召唤部队 | 选玩家，点「选择召唤单位 / 建筑」里的图标加入上方候选框（再点候选图标可拿掉）。列表默认展开，分「单位 / 建筑 / 特殊单位」三块，各自按盟军 / 苏联 / 帝国分组；「特殊单位」放的是建造面板里没有、但对象模板库里登记着的对象（将军刽子手 `JapanMechaKing`、天皇机甲 `JapanEmperorMecha`、钢铁浪人、超级要塞、磁暴坦克……），点一下就进候选框。**本版本模板库里没有的对象会画成暗格**（点不动，悬停会说明），所以不会出现"点了没反应"；旁边的「把可用性写进日志」会把每个特殊单位在模板库里的有无写进 `ra3_overlay.log`。下面还有「搜索全部对象」：输入类型名或中文名片段（如 `Mecha` / `Oni` / `将军`），从模板库里筛匹配项，点一下同样能召唤——战役、特殊和 Mod 单位都在里面；旁边显示模板库总条数，可手动重扫。图标尺寸跟着界面缩放走，右侧预留滚动条宽度，不会被面板边缘裁掉；没有打包图标的对象用名字占位。每种数量默认 1，围着鼠标散开，归所选玩家。旁边的「高度」是在鼠标落点基础上再抬多少（0 = 贴地），气球炸弹这类会自己再抬 3000（贴地生成会当场引爆）；「召唤后立刻可见」默认勾着，清掉引擎给新对象的「隐形 / 未入世」标志；「抬高后停在空中」也默认勾着，每帧把被抬过的召唤物按回召唤高度，旁边显示托着几个、可以一键「放手」让它们落下去。生成排到游戏绘制那一帧，不和单位更新抢同一时刻。热键 `U`，用当前玩家、兵种和数量；按钮旁只留齿轮，不写键名 |

#### 单位操作扩展

面板底部另有一块「单位操作扩展」，对应 CameraBridge 的「选择哪些单位 / 切换单位的队伍 / 在游戏中禁用输入」。只适配原版 Steam 1.12。

| 控件 | 说明 |
|------|------|
| 在游戏中禁用鼠标输入 | 勾上后 overlay 吞掉发往游戏窗口的鼠标消息，游戏不再响应悬停和点击，拍运镜时不会冒出鼠标悬停单位的高亮边框。overlay 自己的菜单不受影响，随时可以关掉 |
| 选择哪些单位 | 下拉：**选中的单位** / **未选中的单位** / **所有的单位** / **指定玩家的单位**。后面两项配一个玩家选择器。右侧实时显示「当前范围命中 N 个单位」。CameraBridge 的「由玩家或 AI 选中的单位」在游戏里就是本组默认的「选中的单位」 |
| 切换单位的队伍 | 把所选范围内的单位改到目标玩家名下（走引擎的 `setTeam`，同时刷新 Team 和归属字段，不改模型）。**启用 AI 操控**：不勾选时改完归属顺手把该单位速度写成 0（原地冻结），免得 AI 立刻把单位调走；勾回来会把冻结的速度还原，所以不用再切一次队伍单位也能动 |

改队伍会让正在录制的录像不同步（和 CameraBridge 的提示一致）。写入前都会校验目标玩家和字段形状，对不上就拒绝并在状态栏说明。

### 摄像机

对应 CameraBridge 的「摄像机操作」，是这个修改器的主力拍摄工具。只适配原版 Steam 1.12（起义时刻下显示「未就绪」）。分开在「当前坐标 / 轨迹与播放 / 定时事件 / 配置」四个页签。

**这里改的是镜头位置，不是单位位置。** 复制 / 移动单位请用「单位操作」（例如复制到鼠标位置）。

**当前坐标**

| 控件 | 说明 |
|------|------|
| 接管摄像机（持续锁定） | 打开后引擎每次设置相机矩阵都会被改成这里的目标值，等于把镜头从游戏手里抢过来。关掉立刻还给游戏。**退出遭遇战时会自动关闭接管并停止轨迹播放**，避免退局拆 View 时还在改矩阵导致卡死（退局音效一直循环） |
| 跟随当前 | 默认开。不接管时数值跟着游戏走，接管后数值跟着你的目标值走 |
| 坐标 X / Y / Z | 镜头世界坐标，Z 轴向上。直接填数即时生效（不在对局里禁止写入） |
| 旋转 偏航 / 俯仰 / 滚转 | 单位为度。换算是 `偏航=atan2(m[4],m[0])`、`俯仰=asin(m[9])`，和引擎 `0x7EC240` 的算法一致 |
| 距离（缩放） | 相机到焦点的距离，最小值 1 |
| 微调 | 位置 / 角度 / 距离三档步长可调，点一下立即生效。适合一帧一帧抠运镜 |
| 把当前值应用到游戏 / 读取游戏当前 / 停止接管 | 手动读写与释放保持 |

**轨迹与播放**

| 控件 | 说明 |
|------|------|
| 插值 | 线性插值 / 贝塞尔曲线 / 平滑样条。线性必定经过节点；贝塞尔把节点当控制点，不一定经过；平滑样条额外保证曲线穿过每个节点 |
| 复制当前坐标并添加节点 | 先把镜头摆到位，点一下就把当前 X/Y/Z/偏航/俯仰/滚转/距离记成节点，可顺手填标签 |
| 节点表 | 每行可改标签、抵达时间、六个姿态分量，还能「用当前」「跳转」（把镜头瞬间移到该节点）「删除」 |
| 播放 / 暂停 / 停止 | 至少两个节点才能播。快捷键 Ctrl+E 播放/暂停，Ctrl+Alt+E 停止，Ctrl+K 记录节点 |
| 循环 / 速度 / 时间条 | 播放倍率 0.1–4.0 倍，时间条可以拖动查看时间轴任意位置 |

**定时事件**

在一个时间点上自动做一件事，对应 CameraBridge 的定时事件。

| 项 | 说明 |
|----|------|
| 基准 | 动画开始后 / 进入对局后 |
| 动作 | 开始播放动画、停止播放动画、暂停/继续动画、跳到指定节点、使用节点坐标、切换功能开关（参数就是左侧功能列表里的任一功能） |
| 触发一次后不自动重置 | 和 CameraBridge 一致，需要手动点「重置已触发」。右上有「n / m 个事件已触发」 |

**配置**

一个配置 = 一条轨迹 + 它的定时事件 + 说明，保存在 DLL 同目录的 `ra3_camera.ini`。可以新建、克隆、改名、写说明、删除、切换；「保存到文件 / 从文件读取」对应 CameraBridge 的 Ctrl+S 和配置加载。

### 时间控制

对应 CameraBridge 沿用自 RA3TimePausePlugin 的「时间操作」。只适配原版 Steam 1.12，目前是**实验性**面板：已验证的旋钮只能加速，减速 / 暂停做不了。

| 控件 | 说明 |
|------|------|
| 写入目标 | 「不改内存」/「只改 logicFPS」（`0x00CB4098`）/「只改 updateFPS」（`0x00CB409C`）/「两者同步」。默认不改内存，选错也不会崩，随时可以切回 |
| 倍率滑块 | 1.0x – 8.0x，1x = 进入对局时读到的原速；低于 1 会被抬到 1。快捷档位 1x / 1.5x / 2x / 3x / 4x / 6x / 8x |
| 恢复原始速度 | 写回进入对局时记录的原值，并停用持续覆盖 |
| 快进到指定对局时间 | 先填目标时间（秒，另有 `+1 分` / `+2 分` 快捷键，可见当前对局时间 mm:ss），再设快进倍率（1–8x）。点「快进至目标时间」后把倍率拉到该值，**到达目标时间后自动回到常速**（不是暂停）。另有「到达目标时间后自动开始快进」和「取消快进」 |

**硬性不变式**：`logicFPS >= 1` 且 `updateFPS >= logicFPS`。引擎 `0x00655166` 用 `edi = updateFPS / logicFPS` 决定每帧跑几次逻辑更新，`edi = 0` 时会在 `0x0065519A` 除零崩溃（实测崩在 `0x25519A`）。所以这里只做加速，不做减速 / 暂停。旧实现写的 `[[0xCE8138]+0x54]` 其实是**亮度**（伽马），早已停止写入；`0x6F91C0` 也不是设速度的函数。对局里每帧只写目标字段，不在热路径里进游戏虚函数；"退出遭遇战"要连续 500ms 都不在对局里才算数（`battle_just_left`），避免在引擎拆 `TheGameLogic` / 玩家列表的那几帧里抢着恢复；诊断探针也只读内存，不再从渲染线程调用会话对象的虚函数。

### 动画 / Lua

对应 CameraBridge 的「动画跟踪 + Lua 桥」。只适配原版 Steam 1.12。进入对局、脚本跑起来之后才就绪。

上半部分是**动画跟踪**，只读展示引擎脚本里的这几个全局变量（缓存约每秒刷新 4 次；读取由游戏线程在执行 Lua API 时完成）：

```
AnimationLuaGetCurrentGameObjectAddress / AnimationLuaGetCurrentGameObjectId
willSwitchAnimation / willSwitchPause / gameTime / relativeTime
```

下半部分是**读写任意 Lua 全局变量**：填变量名和值，点「读取」「写字符串」「写数字」「置为 nil」。写入只入队，由游戏线程在下一次 Lua API 调用时真正执行（写会分配 Lua 内存，不能在渲染线程做），结果写 `lua:` 日志。注意这个定制版 Lua 的类型表里没有独立的 boolean 标签（只有 userdata / nil / number / string / table / function），所以脚本里的开关量如果实际是布尔值，写数字不一定被当成真/假，先「读取」看它原本的类型再决定写什么。

### 杂项操作

对应 CameraBridge 的「杂项操作」，主要面向录视频时的画面调整。只适配原版 Steam 1.12（起义时刻没有对应地址，进入后各控件直接置灰）。

| 功能 | 说明 |
|------|------|
| 不显示血条和维修标志 | 关掉战场单位头顶的血条和维修扳手。写渲染对象 `[0xCE08F0]+0x139` |
| 不显示建筑背后的单位剪影 | 建筑挡住单位时不再画半透明剪影。写同一个对象的 `+0x138` |
| 每帧保持 | 勾上后每帧把上面两项写回，换局或改画质后不会丢 |
| 阴影贴图大小 | 1024 / 2048 / 4096 / 8192，写 `[0xCEEDB4]`。游戏在开局建阴影贴图时才读它，**要重新开始一局（重进地图）才看得到变化** |
| 最大阴影距离 | 拖条选值，**松手或点「应用」后才写入** `[0xCEEDB8]`（浮点，默认 1000）。离相机多远还画阴影，调大可减少远处阴影突然消失 |
| 光照颜色 | 环境光、主光源、调色 #1、调色 #2 四组，写 `[[0xCE0D78]+0x24]` 里的浮点 RGB。分量是 0..1（1.000 相当于 255），**行上只显示色块，点开调色盘选色**（不再并排三个 RGB 输入框） |
| 每帧保持光照颜色 | 默认开。游戏换局会重置光照，勾上后在对局里一直写回你设的值 |
| 恢复默认光照 | 把四组颜色还原成这次注入时第一次读到的值，并关掉保持 |

写入前都会校验指针与当前值（光照分量必须是合理的有限浮点、阴影大小必须是四个档位之一），对不上就拒绝并写 `misc:` 日志，不会盲写。**不在对局里（含退出遭遇战拆设备期间）停止一切阴影 / 光照 / 血条剪影覆写**，目标值保留，下一局进场后自动再应用，避免 Present 卡死。

## 三、战况统计

侧栏打开 **战况统计**。只列出已经进局的玩家：观战席、空座位和中立席不显示。被击败的玩家仍留在榜上，名字旁标「已击败」，折线和累计金额保留，场上数量归零。

- 标题是一颗**玩家颜色色块**加上阵营（盟军 / 苏联 / 帝国），己方后面另标「己方」。观战注入时标题旁有「观战」。
- 卡片上有当前资金、电力，以及场上还活着的部队、建筑（图标 + 数量）。攻击无人机、卫星扫射和帝国点防御无人机不进这张表。

- 纳米核心展开成建筑后，统计里不再留着已经失效的核心（例如超能波毁灭装置建好后的「毁灭装置核心」）。纳米虫群显示为「纳米虫群巢穴」。

## 六、技术原理

### 进程

`RA3.exe` 是启动器。真正的引擎是 `Data\ra3_1.12.game`。主模块无 ASLR，镜像基址 `0x400000`。`.text` / `.rdata` / `.data` 的文件偏移等于 RVA。

菜单画在 `Present` 上。`EndScene` 的钩子不负责画界面。渲染包在 SEH 里，避免一次绘制异常把游戏带走。

### MustCode

点「注入」后，DLL 调用同目录的 `arm_mustcode.dll`（内容仍是装配程序，扩展名做成 dll，避免和 `main.exe` 点错；内含 `keystone.dll`，用 `mustcode_asm.py` 装配），在游戏进程里分配几块内存并打 5 字节 `jmp`：

| 段 | 用途 |
|----|------|
| MustCode | 主要 hook 逻辑 |
| MustCode2 | 单位速度 / 血量 |
| FLAGS | 各功能开关，一字节一个 |
| IDB | 单位数据基址缓存 |

`.text` 默认只读，写补丁前会改页保护，写完再恢复。观战模式跳过 PlayerID、Money、Power、SCPoint、HaveAllSC。

打补丁前先按表里的原始字节**逐条校验** hook 站点：字节对不上（装了 Mod、别的修改器留下的 `E9`、或根本不是这一版）就跳过这条并在日志里点名，只给验证通过的站点打 `jmp`。版本不对时退化成少几个功能，而不是一注入就崩。卸载 / 退局时也只把那几条写回原字节（`arm_hooks` 会再读一次站点，确认 `E9` 确实指向本次的 MustCode 段才记进已装列表）。

17 个 hook（Steam 原版 1.12 VA）。起义时刻对应的 16 个地址见下面第九节：

| Hook | VA | 功能 |
|------|-----|------|
| PlayerID | `0x54119B` | 玩家 ID |
| Money | `0xA64E9E` | 金钱 |
| Power | `0xA64DA7` | 电力（从 `je` 分支头挂，见下） |
| SCPoint | `0xA64EF6` | 科技点（从 `test eax,eax` 分支头挂） |
| HaveAllSC | `0xA64F55` | 全科技 |
| FastBuild1 | `0x74D81E` | 快速建造 |
| FastBuild2 | `0x74D77C` | 快速建造 |
| FastBuild3 | `0x73511F` | 快速建造 |
| SuperPower | `0x729F19` | 超级武器 |
| SuperPower2 | `0x87CB89` | 超级武器 |
| DisableAllSP | `0x87CC16` | 禁用敌方超武 |
| DisableAllSP2 | `0x748A06` | 禁用敌方超武 |
| Map | `0x8005BC` | 消散战争迷雾 |
| UnitAmmo | `0x569D85` | 弹药无限 |
| DangerLevel | `0x877070` | 危险等级 |
| OreMine | `0x712EB3` | 恢复矿场 |
| EnemyCantBuild | `0x74D920` | 敌人无法建造 |

写入前逐条核对原始字节：对不上就跳过这条并在日志里写明「hook X not armed (site bytes differ)」，其余照常装。PlayerID 是注入口的硬门槛——它要是对不上，整次注入会停在 probe failed：多半不是 1.12，或别的修改器已经改过那个位置。

**补丁区间不能包含函数内部跳转的落点。** 5 字节 `E9` 会把整段被偷的字节一起覆盖，如果同一函数里还有一条 `jmp`/`jcc` 落在被偷区间内部（尤其是两条分支合并到同一条指令的地方），那条路就会跳进 `E9` 的位移字节里，把被偷的指令（常见的是 `mov ecx,[esi+…]` 这种寄存器重载）整条跳过去，随后 `call [错误 this + 0xC]` 直接崩。Power 和 SCPoint 就是这样：原站点 `0xA64DAD` / `0xA64F0C` 把「空表」与「非空」两条分支的合并点 `0xA64DB0` / `0xA64F0F` 包进了补丁，电力对象里那张表一旦非空（正常局里绝大多数时候是空的，所以能撑很久）就会 `eip=00000001` 崩在 `call edx` 上。现在两条都改成**从分支头开始挂**（`0xA64DA7` / `0xA64EF6`，偷 15 / 25 字节），stub 里自己重做分支判断，再统一跳回合并点之后。给 hook 选址时按这个规则反汇编站点前后 ±0x40 字节检查一遍，落点在 `[站点, 站点+长度)` 内就往前挪到分支头。

### 另一层：MinHook

上面 17 个（起义时刻 16 个）MustCode hook 是自建 stub。摄像机、时间控制、动画 / Lua、杂项操作这四个面板另外用 MinHook 挂了几处，DLL 载入时由 `init()` 一次装好（`camera_install_hook` / `time_control_install` / `lua_bridge_install` / `misc_install`），装失败只会让对应面板显示「未就绪」，不影响 MustCode 那一层：

| 挂点 | 用途 |
|------|------|
| `0x821760` / `0x7EC240` / `0x7DC060` | 引擎设置相机矩阵与 View 初始化，见上面「摄像机接管」 |
| Lua C API 一组（`0x40A3F0` 起） | 捕获 `lua_State*`，见上面「Lua 桥」 |
| `CreateUnit` / `SpawnObject` / `Destroy` | 单位表快照（更早就装了，不是这四个面板新增的），供统计、建造限制、切换队伍的作用范围使用 |

每帧的推进统一挂在 Present 上：`drain_unit_spawns` → `camera_tick` → `time_control_tick` → `lua_bridge_tick` → `misc_tick` → 画界面。

### 选中单位

原版的速度、血量、摧毁、复制都从选中单位管理器出发：

```
[模块 + 0x8E08DC] = 管理器          绝对地址 0xCE08DC
管理器 +0x5C      = 当前选中数量
管理器 +0x50      = 选中链表头
  节点 +8         → 对象
  对象 +0x138     → 单位实体
  实体 +0x374     → 单位数据（+0x200 速度 / +0x33C 血量）
  实体 +0x3CC     → 经验追踪器
  实体 +0x418     → 归属玩家
```

`0x8E08DC` 是 RVA。函数地址（例如 `0x5173F0`、`0x6440F0`）是已经含基址的 VA。两者不能混用：把 RVA 再按 VA 去减 `0x400000`，会少整整一个基址，读到空列表。

Steam 版是重编译的二进制，零售版全局指针 `0x8DB73C` 在这份模块里没有引用。对象内部偏移 `+0x50 / +0x5C / +0x138` 没变。

### 摄像机接管（`camera.cpp`）

相机状态的真身是 `View+0x08` 的 3×4 矩阵；`+0x38 / +0x3C / +0x40 / +0x44` 只是缓存（X/Y/Z/朝向），`+0x260` 是相机距离。接管点选在引擎唯一的「设置相机矩阵」入口：

| 项 | 地址 | 说明 |
|----|------|------|
| `W3DView::setTransform` | `0x7EC240` | 签名 `__thiscall(const float* m)`，`ecx` = View。实测从不被调用 |
| 第二个 setTransform | `0x821760` | 同样的签名，实际跑的是这个，两个都挂 |
| `W3DView::Init` | `0x7DC060` | `CreateView`（`0x51A210`）建完对象立刻调用，`ecx` = View，每个 View 只调一次，用来第一时间拿到 View 指针 |
| View 登记表 | `0x00CEAAC0` | 槽位 = `0x00CEAAC0 + idx*16`，索引在 `0x00CEAA00`。hook 还没被调用过时从这张表兜底扫描 |
| View 主 vtable | `0x00C54BB0` | 构造 `0x7FFFE0` 写 `[this]`。派生链上还有 `0xC54D30 / 0xC54F60 / 0xC552A0 / 0xC55988 / 0xC55A60 / 0xC55AA0`，扫描时一并接受 |

`camera_apply` 写回前会检查 12 个矩阵分量都是有限浮点：一旦把 NaN/Inf 写进相机对象，游戏后续把它当指针或索引用就会崩溃。轨迹按「线性 / 贝塞尔 / 平滑样条」插值，播放推进和定时事件都在 Present 里走 `camera_tick()`。**不在对局里 hook 不改矩阵、`camera_apply` / 接管会被拒绝；退出遭遇战时 `camera_tick` 自动关掉接管并停止播放**，避免退局拆 View 时卡死 Present。

### 游戏时间倍率（`time_control.cpp`）

全局指针 `0x00CE8138` 指向显示 / 选项缓存对象，但它**不是**速度旋钮：

| 偏移 | 含义 |
|------|------|
| `+0x30` | GameSpeedFactor（只读展示，调试面板里就叫这个名字） |
| `+0x54` | **亮度 / 伽马**，不是时间倍率。`0x6F91C0` 重算的正是它，渲染路径 `0x6232CC` 读它决定 gamma |

真正的速度量是两个全局：`[0x00CB4098]`（logic FPS，正常局 15）和 `[0x00CB409C]`（update FPS，正常局 30）。引擎在 `0x00655166` 算 `edi = updateFPS / logicFPS`，再按 `edi` 决定这帧跑几次逻辑更新；`edi == 0` 会在 `0x0065519A` 除零崩溃（实测崩在 `0x25519A`）。所以写入前必须保证 `logicFPS >= 1` 且 `updateFPS >= logicFPS`，上限分别收在 120 / 240。

**只能加速**：倍率是相对「进入对局时读到的原值」（正常局 updateFPS = 30）的倍数，写值范围 1x–8x。整个 `.text` 里没有任何指令写这两个全局，所以没有原生的「减速 / 暂停」入口可以挂——这就是面板里减速档位全部置灰的原因。`Present` 每帧只写内存，绝不进游戏虚函数；写前校验目标字段指针可读、原值在合理区间。退出遭遇战时写回原值并停写。

快进用同一组字段：把 updateFPS 拉到设定倍率，`Present` 里读对局时钟，到达目标时间就写回 1x 并清掉快进状态（**不会写 0**）。

### Lua 桥（`lua_bridge.cpp`）

内嵌的是 SAGE/Corona 定制版 Lua 5.0。栈上一个值（TValue）16 字节，`+0x00` 是类型标签，`+0x08` 是 `double` / `GCObject*` / `int`；string 的字符数据在 `((TString*)value) + 0x14`。类型表由 `0x40A570`（lua_typename）从名字表 `0xBE2388` 读出：`0 = userdata / 1 = nil / 2 = number / 3 = string / 4 = table / 5 = function / 6 = lightuserdata`。

`lua_State` 里 `+0x00` 是 `top`、`+0x08` 是 `stack_last`、`+0x10` 是 `base`（一个槽 0x10 字节）。`lua_State*` 没有放在全局变量里（脚本对象的 `+0x24` 才是），所以用 MinHook 挂钩这几个 C API，从第一个参数捕获它：

| 地址 | 函数 |
|------|------|
| `0x40A3F0` | `lua_gettop(L)` |
| `0x40A540` | `lua_type(L, idx)` |
| `0x40A7B0` | `lua_tostring(L, idx)`（数字会就地转成字符串） |
| `0x40A8D0` / `0x40A930` / `0x40A9A0` | `lua_pushnil` / `lua_pushnumber` / `lua_pushstring` |
| `0x40AA70` / `0x40ACC0` | `lua_getglobal` / `lua_setglobal` |

写之前先校验 `top/base/stack_last` 都像合法指针、`top` 16 字节对齐；全程 `__try/__except` 兜底；读完把 `top` 还原成调用前的值（等价于弹栈），不依赖 `lua_settop` 在 `idx>=0` 时那条不确定的路径。

### 禁用游戏鼠标输入

没有挂钩子，直接吞消息：`hk_wndproc` 里判断一个原子标志，勾选时把 `WM_MOUSEFIRST..WM_MOUSELAST`、`WM_MOUSEWHEEL`、`WM_MOUSEHWHEEL` 全都 `return 0`，游戏收不到鼠标消息就不做悬停和点击判定，overlay 自己的窗口不受影响（ImGui 走的是自己那套输入）。

### 单位颜色字段

「切换单位的颜色」已经去掉：实测改玩家 `+0x80` 只会让菜单里的色块变，战场上的单位模型颜色不会跟着变（颜色在单位创建时就烘进了渲染对象），留着只会误导。资金 / 战况面板读玩家色的逻辑（`+0x80`，个别版本回退 `+0x84 / +0x88`，`0xAARRGGBB`）没变。

### 切换队伍（归属）

单位身上 `+0x414` 是 Team*、`+0x418` 是 Player*，`Team::getPlayer() = [[team+4]+8]`。只写 `+0x418` 不动 Team 的话，引擎随后会按 Team 里的玩家把 `+0x418` 覆盖回去，表现就是「点了没反应」。现在改归属走引擎自己的 `GameObject::setTeam(Team*, int)`（原版 1.12 = `0x007CBF50`，放进子线程调用），它会同时刷新两个字段、挪动小队 / AI 链表并广播归属变更；目标玩家的 Team 先从地图上属于他的单位身上取，取不到再扫玩家对象里的指针。引擎调用没成立时，退回「Team + Player 一起写」的兜底。

### 满级为什么不在 hook 里调用游戏

`0x5173F0(entity, xp)` 是官方「给单位加经验」入口，内部会进 `ExperienceTrackerObject::SetRank`，由引擎自己派发晋升、EVA 和星星。直接写 `tracker+0x24` 只改缓存，游戏里的星级不变。

这个接口不能在 MustCode hook 里同步调用。玩家更新那条 hook 的调用者已经拿着全局锁 `0xCDDF20`，而加经验一进来又要加同一把非递归锁，会自死锁，游戏画面停住。现有 17 个 hook 都只做内存读写。满级、摧毁、复制、召唤基地车都放到独立线程里再 `call` 游戏函数。

经验追踪器（虚表邻近字符串 `ExperienceTrackerObject`）：

| 偏移 | 含义 |
|------|------|
| `+0x08` | 当前等级的定义键 |
| `+0x0C` | 当前经验（float） |
| `+0x10` | 下一级所需经验 |
| `+0x1C` | 经验倍率 |
| `+0x20` | 最低字节是「等级特效已播放」 |
| `+0x24` | 等级索引缓存，实测约 0–4。写入它不会让星星变化 |
| `+0x2C` | 加成对象 `sub` |
| `sub+0x08` | 当前加成倍率。伤害×5 写的是这里 |

### 出场等级和召唤

出场等级走生产老兵升级：`Upgrade_ProductionVeterancy_VETERAN / _ELITE / _HEROIC`，对应滑条 1 / 2 / 3。查找升级 `0x586CF0`，授予 `Player::setUpgrade` `0x88B800`，清除 `0x888510`。这是累加的，只影响之后生产的单位。

召唤基地车用 `CreateUnit` `0x6440F0`。模板从 Thing 工厂 RVA `0x008EBDE8` 按 `AlliedMCV` / `SovietMCV` / `JapanMCV` 查找，归属是基地车那一栏选中的玩家，落点是鼠标投影到地形的坐标。

召唤部队走的是同一个 `CreateUnit`，区别只在模板怎么找。现在是**先算哈希再直调引擎的 `FindTemplate`**（和 [Ra3-Copilot 的 pipeline](https://probiusofficial.github.io/Ra3-Copilot/units.html#pipeline) 同源）：

- 代码 = `StringHasher.Hash(模板名.lower())`，是 **SuperFastHash 变体**，不是 CRC32 / FNV。`sage_hash_lower()` 是逐字节对应的 32 位实现（已用 Copilot 的 `unit_codes_all.tsv` 逐条对齐，`JapanMechaKing` = `0x450BD734`、`JapanBalloonBombBalloon` = `0x4B688D52`）。
- 引擎那棵哈希树的键其实是**名字的哈希**，不是字符串指针。早先"扫桶 + 逐字节比字符串"根本配不上——名字明明在内存里，表里却查不到，于是特殊单位被判成"本版本没有"。
- `FindTemplate` 与 `ThingFactory` 全局不写死地址：先用 Copilot 的字节签名 `83 EC 08 56 8D 71 28 …` 认函数（RVA `0x3E4230` 对不上就全镜像扫签名，多个同形函数时挑被最多 `mov ecx,[imm]` 指向的那个），再由 `8B 0D <imm32> E8 <rel32→FindTemplate>` 反推全局（取出现次数最多的 imm32），最后用 `JapanMCV` / `AlliedBarracks` 的哈希做探测确认。日志里 `template: find=00822510 factory slot=00CEBDE8 store=04CF09A0 (hits=110)` 就是这一步的结果。
- 调用签名按 Copilot：`__fastcall FindTemplate(store, edx=0, hash)`；返回指针的 vtable 必须落在游戏模块内才交给 `CreateUnit`。

注意这个 store 只收**可建造面板**那 392 条，所以气球炸弹这类战役 / 特殊对象按哈希查不到是正常的（`template hash 4B688D52 -> 00000000`），仍然由字符串兜底找到——两套路径并存，谁也替代不了谁。

**模板库登记的是全部对象类型**，不只是建造面板里能造的那些——所以战役 / 特殊 / Mod 单位（`JapanMechaKing` 将军刽子手、`JapanEmperorMecha` 天皇机甲、`JapanSentinelVehicle` 钢铁浪人……）同样能召唤，前提是**你这个版本里确实有这些模板**（原版 1.12 与起义时刻、以及各个 Mod 的模板库不一样）。

旧路子仍然留着兜底（Thing 工厂 `+0x2C` 桶数组 / `+0x30` 桶数、模板链表 `+0x24`、驻留字符串），但只在哈希查不到时才走。

「搜索全部对象」用的 `object_type_names()` 就是遍历这张哈希表，把注册名收集成排好序的列表（60 秒缓存；扫描失败后 5 秒内不重试），表布局对不上时退回扫模板链表、从模板内存里挖像类型名的串。日志会打 `thing factory: N object type names (buckets=M)`。

这条名单还兼两个职责：

- **负结论**：名单够大（>500 条）时，`find_template_by_id` 先做一次二分查找，名字不在名单里就直接返回 0。以前会落到"全进程内存找驻留字符串"的兜底——那是几十到几百毫秒一次的扫描，跑在渲染线程上连续几个不存在的 id 就会把游戏卡死（玩家看起来就是崩溃）。现在兜底还额外加了 12 ms 时间预算、每 30 秒最多 4 次。
- **UI 判定**：特殊单位里本版本没有的模板画成暗格，点了不会白跑一次失败调用。

创建前还有一道护栏：命中哈希表后的模板指针要看 vtable 是否落在游戏模块内，不像模板就别拿去 `CreateUnit`（表里确实混着技能 / OCL 之类的键）。召唤后按类型统计成功数，哪种没造出来会单独点名（`exists but CreateUnit refused it`），提示里也会写"游戏拒绝创建 X"，而不是笼统的"召唤失败"。

高度：`summon_spawn_lift()` 给气球炸弹这类"落地即爆"的对象自动加 3000 的起始高度（`JapanBalloonBombBalloon` 的模板描述就是 `Slow-Falling Ordnance`，它本身就是会缓慢下落的弹药，贴地生成必当场引爆），面板上的「高度」再额外叠加（0 = 贴地）。

光抬高不够——`CreateUnit` 对地面层对象会把 z 贴回地形，而且对象自身就是"往下掉、碰到地面就炸"，抬多高都只是"从高处掉下来炸"。所以有三层：

1. `post_create_lift()`：创建当帧拿提交的 x/y 在对象内存里配对出坐标副本（本体 Coord3D、子对象、Drawable 变换矩阵的平移分量）并把 z 一起写回去。早期只认第一个命中 `+0x38`，那往往不是渲染用的那一份，所以"高度不生效"。
2. **沿指针下钻的追踪扫描**（`collect_pos_fields_deep`）：真正驱动"下落 + 落地即爆"的那一份坐标常常是**单独分配的 Coord3D 数据块**（12 字节纯数据、没有 vtable，而早期按"子对象必须有 vtable"筛，正好把它漏掉）。现在从对象出发沿指针下钻最多 3 层（只跟堆指针、跳过模块自身的数据段），在 0 / 120 / 320 / 700 / 1400 / 2400 / 3800 / 5600 ms 各采一次样，把新冒出来的副本也收进托举表。第一遍只观察不写，和下一遍比 z，日志里会打出 `air hold: FALLING <obj>+0x<off> z a -> b (dz=...)`——那就是引擎真正在用的位置。
3. `air_hold_tick()`：把所有副本按回召唤高度，`只托不压`。由三条路径驱动：**`BeginScene` 钩子**（逻辑已经走完、刚开始画这一帧——在这里写才赶得上本帧渲染）、Present、以及一根 **8ms 高频线程**。只在 Present 里写是不够的：Present 在"逻辑 → 绘制"之后，下一次物理更新又会把 z 按回地面。

托举表的存活判据**不能**用 `Thing+0x33C` 是 HP 指针：气球炸弹这类是弹药（Ordnance），那儿根本不是血量，结果每条都在下一帧被判死、整张表被清空——这是"高度怎么调都贴地"的第一层原因。现在按来源分两类：本体/子对象要求 vtable 还是当初那个；单独分配的坐标块没有 vtable，只靠"x/y 还贴着召唤点"来判。Destroy 钩子另外会把对象出表。卸载前 `air_hold_shutdown()` 先停掉那根线程，否则 `FreeLibrary` 之后它还在写游戏内存。

面板上的「抬高后停在空中」默认勾着，旁边显示「托着 N 个」和「放手」按钮（清掉托举，让它们按自己的逻辑下落 / 引爆）。日志会打 `summon: thing position field = +0x..`、`summon: created .. pos z=.. want=..`、`summon: raised .. to z=..`，以及每 120 帧一条 `air hold: N held, M pulled back this frame` —— 从这些行能看出引擎是否在和我们抢这个高度字段。

旁边的「召唤后立刻可见」默认勾着：`CreateUnit` 造出来的对象带「隐形 / 未入世」标志（`+0xC8` bit `0x800`、`+0x28` / `+0x208` 的 bit31），不清掉就会出现"召唤了但场上什么也看不到"（Copilot 那边是同一套标志位）；置 `+0xBC` bit31 再清这三位。写之前先验 `Thing+0x33C` 是不是 HP 结构指针，对不上就跳过，不硬写。

参考实现：`Ra3-Copilot` 是「按名字哈希」在同一个模板库里直接 `FindTemplate(hash)`，再 `CreateUnit(0, tmpl, pos, team, team+0x10)`，并额外补写创建后的状态字（Thing `+0x80/+0x84/+0x88/+0x90/+0x94/+0xD0`）和清掉 `+0xC8/+0x28/+0x208` 的「未入世 / 隐形」位，让召唤出来的单位技能和护盾可用。本仓库目前只做前者（找模板 + 创建），没有补状态字，因为实机召唤出来的单位已经能用。

### 加载战局时不要在游戏线程里分配

CreateUnit / SpawnObject / Destroy 的钩子只把指针放进固定数组，分类和建表放到界面线程。重扫单位表会等约 2.5 秒。建造限制要等战局时钟有效满 3 秒。加载存档时游戏自己的分配器可能返回空，紧接着读 `[NULL-4]`；如果钩子在同一条游戏线程上做堆分配，就会撞上这次崩溃。

崩溃日志记异常码、EBP 回溯，以及栈上能认出的模块偏移，写在 `ra3_overlay.log.crash`（跨会话累加，不随注入清空）；主日志里同时留一行 `CRASH captured (...)`，方便按时间线对照。

### 卸载/重注入时不能再跑 detour

注入器每次注入前会先 `FreeLibrary` 掉旧的覆盖层。游戏这时还在跑渲染线程，如果 `DllMain(DLL_PROCESS_DETACH)` 里继续让 `Present` detour 干活、或者跨线程去释放 D3D/ImGui 资源，等 DLL 被映射掉之后 EIP 就停在裸内存上——WER 里正是 `ra3_overlay_v4.dll_unloaded` + `c0000005`（实测 2026-10-24 12:14 那次）。现在的卸载顺序：

1. 立 `g_unloading` 旗标，`Present / EndScene / Reset / SwapChain::Present` 四个 detour 立刻只转发原函数；
2. 还原窗口过程（它是游戏消息循环会进来的指针，必须先从我们代码上摘掉）；
3. `MH_DisableHook` 卸掉内联钩子；
4. 等 `g_present_inflight` 归零（Present 可能被 vsync 卡住，最多 800 ms），再停线程，超时就 `TerminateThread`；
5. 界面资源**故意不在这条路径上释放**，跟着进程一起走。

进程退出（`DllMain` 的 `reserved != NULL`）则什么都不做：那时候其它线程已经被系统随机终止，任何清理都是在碰已经死掉的对象。

### 换模式时的空指针

遭遇战结束后，玩家列表全局有时还指着已经释放的内存。脚本按座位取玩家时，读不到就当成没有这个玩家，继续往下走，不会把整张玩家表换成别的对象。AI 选择超武时，查找结果为空就跳过这一次。这两处在 DLL 载入时就装上。日志里应有 `ai power null guard`、`script player guard` 和 `player slot guard sites=2`。

### 存档里没有折线

遭遇战存档在「保存的游戏」目录下，例如：

```
C:\Users\<用户>\Saved Games\Red Alert 3\<档案号>\<名字>.RA3Skirmish
```

档案号来自 `%AppData%\Roaming\Red Alert 3\Profiles\directory.ini` 的 `CurrentProfile`。游戏用 `FOLDERID_SavedGames` 拼出这条路径。存档是 RGMH 头加 BLOK 块的快照（玩家、GameLogic、地图状态），里面没有逐秒统计。所以折线在开始记录之前只能从 0 直线连到当时的累计值。

## 七、编译

### 菜单 DLL

需要 VS Build Tools（x86）和 CMake：

```bat
cd overlay
build.bat
```

`build.bat` 不写死盘符，按这个顺序找 Visual Studio：环境变量 `RA3_VS`（或 `VS`）→ 各盘的 `\visualstudio` →
`%ProgramFiles%` 下的 2022/2019 标准安装位置。装在别处就显式指定：

```bat
set RA3_VS=H:\visualstudio
build.bat
```

`build\CMakeCache.txt` 会记住编译器的绝对路径，VS 换盘或重装后脚本发现缓存失效会自动重建。

输出 `overlay\bin\ra3_overlay_v4.dll`。编完后重新运行注入器。

### 注入器

需要 Python、PyInstaller 和 keystone-engine：

```bat
cd overlay
build_injector.bat
```

脚本会先自动跑一遍 `build.bat` 把 DLL 编出来再打包（否则 `main.exe` 里会包着一份旧的 DLL，新加的界面在游戏里看不到）。已经单独编过 DLL、只想重打包时用 `build_injector.bat norebuild`。

注入器会把当时的 DLL、`arm_mustcode.dll`、名字表和图标打进去。

单文件 exe 的解包目录用 `--runtime-tmpdir` 钉在 `%LOCALAPPDATA%\RA3Overlay\pyi`：PyInstaller 引导器会自己把这棵树建出来，再把 `_MEI<pid>xxxxxx` 放进去，不再依赖 `%TEMP%` 是否还存在 / 是否可写。正常退出时引导器会删掉自己那层目录；异常退出残留的 `_MEI*`（每个约 20 MB）在修改器没运行时可以手动删。

输出：

- `overlay\bin\main.exe`（发给别人只需要这一个文件）
- `overlay\bin\arm_mustcode.dll`（装配程序，扩展名是 dll，避免被当成要双击的程序；玩家那边由注入器自己释出）

若改过 `mustcode_body.asm` / `payload.py`，先在仓库根目录：

```bat
python gen_payload.py
```

`payload.py` 头部写着「自动生成」，但里面最后那一段（`EP1_CORE_HOOKS` + `ep1_asm_and_symbols`，起义时刻的 hook 表和偏移改写）是手写的，生成器不产生它。`gen_payload.py` 现在会把旧 `payload.py` 里这一段原样接回去，重复执行结果逐字节一致；找不到标记而文件里确实有起义时刻代码时会直接报错停下，而不是悄悄把起义时刻支持删掉（删掉以后 `arm_mustcode.py` 顶部那条 import 会失败，两个版本都装不上）。

Windows 安全中心有时会把注入器隔离。这是附加进程、写内存时的启发式误报。在「病毒和威胁防护 → 排除项」里加上本仓库目录或 `overlay\bin`，再从防护历史里还原文件。

| 日志出现 `hook X not armed (site bytes differ)` | 只有那一条 hook 的站点字节对不上（Mod / 旧补丁），该功能失效，其余照常。先卸掉其它修改器再重新注入 |

只支持 Steam 原版 1.12 和起义时刻 1.0。其它版本的基址和原始字节对不上，注入会在 probe 处停住。

## 九、起义时刻（Uprising 1.0）

### 版本与引导

- 只适配 `ra3ep1_1.0.game`（起义时刻 1.0）。启动选项填 `-runver 1.0`。
- 若在跑起义时刻的其它版本（例如 `ra3ep1_1.1.game`），注入器不注入，改弹起义时刻专用的两张图，提示改成 `-runver 1.0`。
- 起义时刻**不做**原版那条严格版本校验：模块是 `ra3ep1_1.0.game` 就注入。原版校验仍只作用于 `ra3_1.12.game`。
- 起义时刻跳过针对零售二进制的引导补丁（观测者字节、空指针守卫等），只装起义时刻自己的 hook 表。

### hook 表（起义时刻 1.0 VA）

16 个 hook，地址和原始字节都按起义时刻重新定位过。这 16 条 AOB 已直接对着 `Data\ra3ep1_1.0.game` 按 PE 节表逐条离线校验（16/16 全中），镜像基址同为 `0x400000`、同样关掉 ASLR 且无重定位表，所以装配程序里那句「基址固定」对两个版本都成立：

| Hook | VA | 功能 |
|------|-----|------|
| PlayerID | `0x54915B` | 玩家 ID |
| Money | `0xA7C7FA` | 金钱 |
| Power | `0xA7C6F2` | 电力（读 `[esi+0x3E0]`，从分支头挂） |
| SCPoint | `0xA7C852` | 科技点（从分支头挂） |
| HaveAllSC | `0xA7C8B1` | 全科技 |
| FastBuild1 | `0x76090E` | 快速建造 |
| FastBuild2 | `0x76086C` | 快速建造 |
| FastBuild3 | `0x74221F` | 快速建造（时间戳在 `[edi+0x34]`） |
| SuperPower | `0x73BB19` | 超级武器（拥有者在 `[eax+0x428]`） |
| SuperPower2 | `0x88C3C9` | 超级武器 |
| DisableAllSP | `0x88C456` | 禁用敌方超武 |
| DisableAllSP2 | `0x75BC06` | 禁用敌方超武 |
| Map | `0x80B9DF` | 消散战争迷雾（写 `[ebp+0x264]`） |
| UnitAmmo | `0x571525` | 弹药无限 |
| DangerLevel | `0x886940` | 危险等级 |
| EnemyCantBuild | `0x760A1D` | 敌人无法建造 |

比原版少一个 **OreMine**（恢复矿场）：起义时刻里找不到既唯一又和零售版同形的落点，宁可不装也不乱挂钩子，所以起义时刻下「恢复矿场」开关不生效。

### 字段偏移

起义时刻是重新编译的二进制，多个结构体变大，同一字段往后挪。已适配的：

| 位置 | 原版 | 起义时刻 |
|------|------|----------|
| 单位实体 · 单位数据 | `+0x374` | `+0x384` |
| 单位实体 · 血量对象 | `+0x33C` | `+0x34C` |
| 单位实体 · 归属玩家 | `+0x418` | `+0x428` |
| 单位实体 · 经验追踪器 | `+0x3CC` | `+0x3DC` |
| 单位数据 · 速度控制 | `+0x200` | `+0x20C` |
| 玩家 · 电力对象 | `+0x74` | 未变 |
| 玩家 · 资金 | `+0xE4` | 未变 |
| 玩家列表全局 | `0x8EDE2C` | `0x9009C4` |
| GameLogic 全局 | `0x8DDE84` | `0x8F0808` |
| 迷雾全局 | `0xCE8130` / `0xCEDE2C` | `0xCFAB30` / `0xD009C4` |

单位相关偏移统一走 `ent_off()`，切换游戏时一起变，避免漏改某个功能。

**装配脚本里的绝对地址只对原版有效**：`mustcode_body.asm` 里有 9 个原版绝对地址、共 25 处 `MOD+0x...` 引用（`0x8E08DC` 选中单位表、`0x8E6C58`、`0x8DAEFC` 鼠标投影、`0x8E9838` ID 魔数，以及 `0x35C200` / `0x39EA50` / `0x3E4230` / `0x2440F0` / `0x1ED4A0` 五个函数入口），起义时刻没有对它们做重定位。它们全部落在 `FLAGS+0x20` 派发区里（`MC+0x600`～`MC+0x1200` 之间那段辅助代码，以及整个 MC2 段），而当前没有任何代码写入 `FLAGS+0x20`（`set_flag` 只用到 `0x0D`/`0x0E`/`0x12`/`0x13` 这些低偏移），所以这 25 处在起义时刻是死代码，不会被跳到。要重新启用那条派发链，必须先把这 9 个地址按起义时刻重新定位，否则会 `call` 进无关函数。

### 起义时刻的功能可用性

可用：

- **资源**：己方资金、选中玩家资金、电力无限、科技点无限、全科技、快速建造
- **超武 / 地图**：超级武器、禁用超武、消散战争迷雾、敌人无法建造、协议无冷却、单位技能无冷却、禁用敌方协议
- **单位操作**：弹药无限、危险等级，超速 / 慢速 / 冻结 / 恢复速度，无敌 / 残血 / 恢复血量
- **战况统计**：资金、电力，以及本局折线（建造 / 损失 / 消灭 / 收入 / 支出）

暂不可用（菜单会直接给「…暂未适配」「未找到游戏模块」的提示，不会静默失败，更不会去调用零售版地址）：

- 恢复矿场（起义时刻未装对应 hook）
- 复制、摧毁、满级、收编、伤害×5
- 召唤基地车、召唤部队
- 建造限制（起义时刻的建造接口未适配）
- 战况统计卡片上的部队 / 建筑 / 协议数量（起义时刻不做单位表扫描，只显示资金和电力）
- **摄像机**、**时间控制**、**动画 / Lua**、**杂项操作**四个面板（相机矩阵入口、时间倍率全局、Lua C API、渲染 / 光照 / 阴影全局都是原版地址）
- **单位操作扩展**：选择范围、切换队伍、禁用鼠标输入

### 已修的两个问题

**1）多出一行「玩家 己方 已击败」**

起义时刻在对局初始化之前，`ThePlayerList` 会先暴露一个未初始化的占位本地玩家（ID 0，没有资金对象）。战况面板一旦把它记进历史，零点几秒后被真正的本地玩家取代时，这个旧快照就从当前席位里消失了，于是被当成「已战败的席位」重新插回榜单。

修法：仅起义时刻启用占位判别（本地 + `player_id==0` + 没有资金对象），在录入、入场判断、战败回填和清理四条路径上都过滤，并做一次历史清洗。

**2）新造出来的单位自己往别处跑**

原版「消散战争迷雾」挂在 `0x8005BC`，改的是相机 / 视野对象里的 `[ebp+0x260]`（相机距离）。起义时刻同一个构造函数整体后移 4 字节，这条指令搬到 `0x80B9DF` 并写成 `[ebp+0x264]`；而零售版那条字节特征在起义时刻里匹配到了**构造函数内部**一个默认值 1.0 的字段。开关一开就把那个字段写成 100000.0，视野对象被写坏，屏幕↔世界坐标与集结点解算随之出错，表现就是新单位像被别的 AI 指挥一样跑向错误坐标。

修法：起义时刻的 Map hook 改用 `0x80B9DF` / 字节特征 `f30f118564020000`，stub 里也只改 `[ebp+0x264]`。两处替换长度不变，hook 段的偏移布局不受影响。

为排除同类隐患，本次逐个反汇编了两个版本的全部 stub，确认它们按原顺序重放了原始指令的助记符与操作数（原版 17 个 + 起义时刻 16 个，全部通过），因此起义时刻不存在第二处同类错位。
