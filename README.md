# 红警3 Steam 版进程内菜单

《命令与征服：红色警戒3》的进程内菜单，同时支持 **原版 Steam 1.12** 和 **起义时刻 1.0**。DLL 注入游戏逻辑进程，用 ImGui 改 MustCode、FLAGS 和单位内存。不改游戏目录里的文件。

- 游戏版本：**Steam 原版 1.12**（进程模块 `ra3_1.12.game`）与 **起义时刻 1.0**（进程模块 `ra3ep1_1.0.game`）
- 形态：Win32 (x86) DLL `overlay\bin\ra3_overlay_v4.dll`，挂在 D3D9 的 Present 上绘制
- 注入：`overlay\bin\main.exe` 把 DLL 载入游戏；菜单里的「注入」再装配 MustCode
- 语言：菜单为简体中文

两个游戏各有一套 hook 表（地址、原始字节、字段偏移都不同），运行时按已加载的模块名自动切换：`ra3_1.12.game` 走原版表，`ra3ep1_1.0.game` 走起义时刻表，互不影响。原版功能不因支持起义时刻而改动。

摄像机、时间控制、动画 / Lua、杂项操作这四个面板，以及单位操作扩展（选择范围 / 切换队伍 / 切换颜色 / 禁用鼠标输入），对应的是另一个视频拍摄插件 **CameraBridgeRelease** 的功能，目前只适配原版 Steam 1.12；在起义时刻下这些面板会显示「未就绪 / 暂未适配」并置灰，不会静默失败。

> **仅供单机 / 遭遇战娱乐与逆向学习。** 不要在线上对战使用。
> 仓库不含游戏本体。

编译步骤、目录和排错补充见 [overlay/README.md](overlay/README.md)。

## 快速开始

1. Steam 库 → 右键游戏 → 属性 → 启动选项：**原版**填 `-runver 1.12`，**起义时刻**填 `-runver 1.0`（两个游戏各自的启动选项）。建议窗口化进入遭遇战。
2. 进局后，**以管理员身份**运行 `overlay\bin\main.exe`。弹窗标题就是结果：**注入成功** 或 **注入失败**；失败时正文写原因（没找到游戏、没有管理员权限、DLL 没载入）。如果运行的版本不对（原版不是 `ra3_1.12.game`，或起义时刻不是 `ra3ep1_1.0.game`），注入会失败，并按对应游戏弹出两张 Steam 属性的截图：在启动选项里填对应的 `-runver`，然后完全退出再重新进游戏。若 `Ra3.BattleNet.Client.exe` 或 `RA3BattleNet.exe` 正在运行（安装目录不限），修改器不会启动，提示「请关闭战网进程（RA3BattleNet）」。
3. 游戏内按 **Home**（或 Insert / F8）打开菜单。观战开局先勾选 **「观战模式」**，再点 **「注入」**。

改过 DLL 之后必须重新注入。游戏里仍是上一次注入的那份。

日志在注入器同目录：`overlay\bin\ra3_overlay.log`。普通记录和崩溃堆栈都写在这里，每次重新注入会先清空。DLL 路径解析失败时才会退到系统临时目录。

发给别的玩家时，只拷贝 `overlay\bin\main.exe` 即可。第一次运行会在这个 exe 旁边释出 `ra3_overlay_v4.dll`、`arm_mustcode.dll` 和 `unit_names_csf.txt`。`arm_mustcode.dll` 仍是装配程序，只是扩展名改成 dll，避免和 `main.exe` 点错。已有的 `unit_names.txt` 不会被盖掉。单位图标在 DLL 内部，不再写出 `unit_images` 文件夹。界面、热键和日志写在 exe 旁边（`overlay_ui.ini`、`ra3_overlay.log`），摄像机配置写在 `ra3_camera.ini`（同一个目录）。原版和起义时刻的版本引导图都留在注入器内部。本机如果还留着仓库根目录的旧界面文件，下次注入会把它复制到 DLL 旁边。

### 界面约定

窗口默认约 900×720，左侧分类，右侧功能页。

| 控件 | 怎么用 |
|------|--------|
| 开关 | 资源、超武/地图、单位操作里一行三个。点名称或开关 |
| 危险等级 | 与名称同一行的三段：正常 / 高 / 最高 |
| 己方资金 | 「+」「-」。点名称可改每次金额，默认 10 万。热键只加、不减 |
| 选中玩家资金、出场等级、召唤基地车、召唤部队 | 整行：先点玩家（颜色方块 + 阵营名），再操作 |
| 一次性操作 | **执行**。复制、摧毁、召唤等在后台做，避免卡住画面 |
| 热键 | 功能名旁的齿轮，可改键。悬停能看到当前热键 |

四项玩家选择互不影响：资金、出场等级、召唤基地车、召唤部队各记各的。只列出已经进局的玩家；己方标「己方」，被击败的标「已击败」。

菜单最下方有选中单位检查：选中后显示实体指针、血量、速度、星级。

**界面设置**里可以调缩放（0.70–1.30，默认 1.00）和背景透明度（35%–100%，默认 80%）。

### 观战模式

勾选「观战模式」再点「注入」时，不装这 5 个资源 hook：PlayerID、Money、Power、SCPoint、HaveAllSC。电力无限、科技点无限、全科技在观战下不可用，用来避免进局闪退。速度、血量、满级、摧毁、复制、召唤基地车、召唤部队仍可用。复制时若没有本地玩家归属，会提示失败。钩子在点「注入」后立刻装上。

载入存档时游戏内存池偶尔扩容失败，原逻辑不判断空指针，会去读 `0xFFFFFFFC` 然后退出。菜单在分配器返回空时改从进程堆补一块同样布局的内存，加载可以继续。日志里若出现 `pool returned null` 就是走了这条补救。

没有单独的观战页。

### 超武 / 地图

| 功能 | 说明 |
|------|------|
| 超级武器 | 超级武器无冷却。热键 Ctrl+F6 |
| 禁用超武 | 拖住敌方超级武器冷却（己方单位技能和协议不受影响；敌方单位技能可能一并被拖）。打开时还会把六座超级武器建筑加入建造限制。读档或战局还没跑起来时先不改冷却、也不调用游戏的建造限制，等场上出现单位约 2 秒（空场则等战局时钟走动约 12 秒）再生效，避免读档时把空的生产队列扩容写崩。开关本身会一直保持勾选。热键 Ctrl+F7 |
| 消散战争迷雾 | 打开后马上清掉整张地图的战争迷雾，高地和还没探索的地方也一起清掉，不用再造建筑或走动。关掉或卸载后按原来的探索结果恢复。热键 Ctrl+F9 |
| 敌人无法建造 | 敌方无法建造。热键 Ctrl+F10 |
| 协议无冷却 | 开关。打开后一直清掉己方协议冷却，关掉恢复。和「单位技能无冷却」「超级武器」共用同一处 hook，其中任一开着，冷却就一直被清掉 |
| 单位技能无冷却 | 开关。打开后一直清掉己方单位技能冷却，关掉恢复。和协议无冷却是同一处 hook |
| 禁用敌方协议 | 开关。打开后一直拖住敌方协议冷却，关掉恢复。不会像「禁用超武」那样把超级武器建筑加入建造限制 |

要单独禁止某一座超级武器，用建造限制里的图标，不要开「禁用超武」。

|------|------|

### 单位操作

本组默认要先在游戏里选中单位。出场等级、召唤基地车和召唤部队不用选单位，它们用自己的玩家列表。

| 功能 | 说明 |
|------|------|
| 超速 ×500 / 慢速 ×10 / 冻结 / 恢复速度 | 改选中单位速度。热键 `-` / `=` / PageUp / PageDown |
| 无敌 / 残血(1点) / 恢复血量 | 改选中单位血量。热键 `[` / `]` / `\` |
| 满级(3星) | 在独立线程里调官方加经验接口 `0x5173F0`，循环到该单位等级不再上升。星星、加成和 EVA 由引擎自己处理。热键 `P` |
| 摧毁选中 | 调官方摧毁接口 `0x7DCDF0`。热键 Delete |
| 复制选中 | `CreateUnit`（`0x6440F0`）在鼠标地图落点生成。正常归己方，观战归原阵营。鼠标要在地形上。热键 `I` |
| 复制到己方 | 同上，归属强制本地玩家 |
| 批量复制 | 每个选中模板在鼠标附近各复制 5 份 |
| 收编敌方 | 把选中单位的归属改成本地玩家 |
| 一键满状态 | 满血，短暂打开弹药无限约 0.3 秒，再尽量满星 |
| 伤害×5 | 写星级加成倍率（`sub+0x08`）。单位之后再升星时，引擎可能按倍率表重算 |
| 出场等级 | 选玩家后拖动 0–3。0 为不设置；1–3 只影响该玩家之后生产出来的单位，不改已经在场上的 |
| 召唤基地车 | 选玩家，再点盟军 / 苏联 / 帝国基地车图标，在鼠标所在地形召唤一辆，归该玩家 |
| 召唤部队 | 选玩家，点三家部队图标加入上方候选框（再点候选图标可拿掉；不含建筑）。三家下面另有「特殊单位」，目前是磁暴坦克。每种数量默认 1，围着鼠标散开，归所选玩家。生成排到游戏绘制那一帧，不和单位更新抢同一时刻。热键 `U`，用当前玩家、兵种和数量；按钮旁只留齿轮，不写键名 |

#### 单位操作扩展

面板底部另有一块「单位操作扩展」，对应 CameraBridge 的「选择哪些单位 / 切换单位的队伍 / 在游戏中禁用输入」。只适配原版 Steam 1.12。

| 控件 | 说明 |
|------|------|
| 在游戏中禁用鼠标输入 | 勾上后 overlay 吞掉发往游戏窗口的鼠标消息，游戏不再响应悬停和点击，拍运镜时不会冒出鼠标悬停单位的高亮边框。overlay 自己的菜单不受影响，随时可以关掉 |
| 选择哪些单位 | 下拉：**选中的单位** / **未选中的单位** / **所有的单位** / **指定玩家的单位**。后面两项配一个玩家选择器。右侧实时显示「当前范围命中 N 个单位」。CameraBridge 的「由玩家或 AI 选中的单位」在游戏里就是本组默认的「选中的单位」 |
| 切换单位的队伍 | 把上面所选范围内的单位改到目标玩家名下（写归属 `+0x418`，不改模型）。**启用 AI 操控**：不勾选时改完归属顺手把该单位速度写成 0（原地冻结），免得 AI 立刻把单位调走；这不是引擎级的「禁止 AI」，只是冻结，用「恢复速度」可以解冻 |
| 切换单位的颜色 | 选一个玩家，拖动调色板后点「应用颜色」。**改的是玩家对象的颜色字段（`+0x80`），所以会波及该玩家的全部单位**，不是只染选中的那几个。「恢复原来的颜色」写回第一次改色前缓存的原值 |

改队伍会让正在录制的录像不同步（和 CameraBridge 的提示一致）。写入前都会校验目标玩家和字段形状，对不上就拒绝并在状态栏说明。

### 摄像机

对应 CameraBridge 的「摄像机操作」，是这个修改器的主力拍摄工具。只适配原版 Steam 1.12（起义时刻下显示「未就绪」）。分开在「当前坐标 / 轨迹与播放 / 定时事件 / 配置」四个页签。

**当前坐标**

| 控件 | 说明 |
|------|------|
| 接管摄像机（持续锁定） | 打开后引擎每次设置相机矩阵都会被改成这里的目标值，等于把镜头从游戏手里抢过来。关掉立刻还给游戏 |
| 跟随当前 | 默认开。不接管时数值跟着游戏走，接管后数值跟着你的目标值走 |
| 坐标 X / Y / Z | Z 轴向上。直接填数即时生效 |
| 旋转 偏航 / 俯仰 / 滚转 | 单位为度。换算是 `偏航=atan2(m[4],m[0])`、`俯仰=asin(m[9])`，和引擎 `0x7EC240` 的算法一致 |
| 距离（缩放） | 相机到焦点的距离，最小值 1 |
| 微调 | 位置 / 角度 / 距离三档步长可调，点一下立即生效。适合一帧一帧抠运镜 |
| 把当前值应用到游戏 / 读取游戏当前 / 停止接管 | 手动读写与释放保持 |

**轨迹与播放**

| 控件 | 说明 |
|------|------|
| 插值 | 线性插值 / 贝塞尔曲线 / 平滑样条。线性必定经过节点；贝塞尔把节点当控制点，不一定经过；平滑样条额外保证曲线穿过每个节点 |
| 复制当前坐标并添加节点 | 先把镜头摆到位，点一下就把当前 X/Y/Z/偏航/俯仰/滚转/距离记成节点，可顺手填标签 |
| 节点表 | 每行可改标签、抵达时间、六个姿态分量，还能「用当前」「跳转」（把镜头瞬间移到该节点）「删除」 |
| 播放 / 暂停 / 停止 | 至少两个节点才能播。快捷键 Ctrl+E 播放/暂停，Ctrl+Alt+E 停止，Ctrl+K 记录节点 |
| 循环 / 速度 / 时间条 | 播放倍率 0.1–4.0 倍，时间条可以拖动查看时间轴任意位置 |

**定时事件**

在一个时间点上自动做一件事，对应 CameraBridge 的定时事件。

| 项 | 说明 |
|----|------|
| 基准 | 动画开始后 / 进入对局后 |
| 动作 | 开始播放动画、停止播放动画、暂停/继续动画、跳到指定节点、使用节点坐标、切换功能开关（参数就是左侧功能列表里的任一功能） |
| 触发一次后不自动重置 | 和 CameraBridge 一致，需要手动点「重置已触发」。右上有「n / m 个事件已触发」 |

**配置**

一个配置 = 一条轨迹 + 它的定时事件 + 说明，保存在 DLL 同目录的 `ra3_camera.ini`。可以新建、克隆、改名、写说明、删除、切换；「保存到文件 / 从文件读取」对应 CameraBridge 的 Ctrl+S 和配置加载。

### 时间控制

对应 CameraBridge 沿用自 RA3TimePausePlugin 的「时间操作」。只适配原版 Steam 1.12。

| 控件 | 说明 |
|------|------|
| 启用时间控制 | 关掉立刻恢复原速 |
| 目标倍率滑块 | 0.000x – 4.000x，**0 等于暂停游戏逻辑**：单位和弹道静止，但镜头仍可自由操作，很适合做运镜 |
| 快捷档位 | 暂停 (0x) / 1/4 速 / 半速 / 常速 / 2x / 4x |
| 恢复原始速度 | 写回进入对局时读到的那一份倍率，并停用持续覆盖 |
| 快进到指定对局时间 | 先填目标时间（秒，另有 `+1 分` / `+2 分` 快捷键，可见当前对局时间 mm:ss），再设快进倍率（1–20x）。点「快进至目标时间」后把倍率拉到该值，**到达目标时间自动把倍率写成 0（暂停）**。另有「到达目标时间后自动开始快进」和「取消快进」 |

倍率每帧写回以保持生效。左侧栏的「时间控制」分组页还有一组现成按钮（暂停 / 慢放 0.5x / 常速 / 快放 2.0x / 快放 3.0x / 恢复），和这块面板改的是同一个值。

### 动画 / Lua

对应 CameraBridge 的「动画跟踪 + Lua 桥」。只适配原版 Steam 1.12。进入对局、脚本跑起来之后才就绪。

上半部分是**动画跟踪**，只读展示引擎脚本里的这几个全局变量（约每秒刷新 4 次）：

```
AnimationLuaGetCurrentGameObjectAddress / AnimationLuaGetCurrentGameObjectId
willSwitchAnimation / willSwitchPause / gameTime / relativeTime
```

下半部分是**读写任意 Lua 全局变量**：填变量名和值，点「读取」「写字符串」「写数字」「置为 nil」。注意这个定制版 Lua 的类型表里没有独立的 boolean 标签（只有 userdata / nil / number / string / table / function），所以脚本里的开关量如果实际是布尔值，写数字不一定被当成真/假，先「读取」看它原本的类型再决定写什么。

### 杂项操作

对应 CameraBridge 的「杂项操作」，主要面向录视频时的画面调整。只适配原版 Steam 1.12（起义时刻没有对应地址，进入后各控件直接置灰）。

| 功能 | 说明 |
|------|------|
| 不显示血条和维修标志 | 关掉战场单位头顶的血条和维修扳手。写渲染对象 `[0xCE08F0]+0x139` |
| 不显示建筑背后的单位剪影 | 建筑挡住单位时不再画半透明剪影。写同一个对象的 `+0x138` |
| 每帧保持 | 勾上后每帧把上面两项写回，换局或改画质后不会丢 |
| 阴影贴图大小 | 1024 / 2048 / 4096 / 8192，写 `[0xCEEDB4]`。游戏在开局建阴影贴图时才读它，**要重新开始一局（重进地图）才看得到变化** |
| 最大阴影距离 | 拖条改 `[0xCEEDB8]`（浮点，默认 1000）。离相机多远还画阴影，调大可减少远处阴影突然消失 |
| 光照颜色 | 环境光、主光源、调色 #1、调色 #2 四组，写 `[[0xCE0D78]+0x24]` 里的浮点 RGB。分量是 0..1（1.000 相当于 255），点色块开调色板，也能直接填大于 1 或小于 0 的数 |
| 每帧保持光照颜色 | 默认开。游戏换局会重置光照，勾上后一直写回你设的值 |
| 恢复默认光照 | 把四组颜色还原成这次注入时第一次读到的值，并关掉保持 |

写入前都会校验指针与当前值（光照分量必须是合理的有限浮点、阴影大小必须是四个档位之一），对不上就拒绝并写 `misc:` 日志，不会盲写。

## 三、战况统计

侧栏打开 **战况统计**。只列出已经进局的玩家：观战席、空座位和中立席不显示。被击败的玩家仍留在榜上，名字旁标「已击败」，折线和累计金额保留，场上数量归零。

- 标题是一颗**玩家颜色色块**加上阵营（盟军 / 苏联 / 帝国），己方后面另标「己方」。观战注入时标题旁有「观战」。
- 卡片上有当前资金、电力，以及场上还活着的部队、建筑（图标 + 数量）。攻击无人机、卫星扫射和帝国点防御无人机不进这张表。
- **协议**单独一行，图标加数量。悬停可看名称：冷却中显示剩余秒数，否则显示就绪。精简视图同样有这一行。
- 纳米核心展开成建筑后，统计里不再留着已经失效的核心（例如超能波毁灭装置建好后的「毁灭装置核心」）。纳米虫群显示为「纳米虫群巢穴」。
- **本局**是一张折线图，五条线：建造、损失、消灭（部队和建筑加在一起），以及收入、支出。数量和金额各自按自己的最大值缩放，避免金额把前三条线压扁。鼠标悬停可看该时刻的时间、部队与建筑的拆分，以及收入、支出金额。
- 横轴从战局 **0:00** 画到现在。游戏记分板和存档只保存累计总数（ScoreKeeper：收入、支出、建造、损失、消灭），不保存逐秒曲线。开始记录之前的那一段，是从开局的 0 连到当时的官方累计值，之后按实际采样画。右端始终是当前的完整统计。
- 采样大约每秒一次；数值没变时会把点抽稀。超过约 1800 个点后保留起点、隔点保留中间、并保留最新一点。
- 「固定」默认关闭。不固定时，关掉主菜单会一起关掉战况窗口；勾上固定后，Home 只关主菜单。每次重新注入都会回到不固定。
- 「精简」不画折线。每个玩家第一行是名字，资金和电力写在同一行并标明。下面部队一行、建筑一行，用图标和数量。勾选会记在 `overlay_ui.ini` 里。

图标编进 DLL。源图仍放在仓库根目录的 `unit_images\`，`build.bat` 打包时读它。文件名用游戏/Wiki 中文名（不含 `.png`），按阵营分子目录：

```
unit_images/
  盟军/{单位,建筑,协议}/
  苏联/{单位,建筑,协议}/
  帝国/{单位,建筑,协议}/
  中立单位建筑/     # 医院、车库、船坞、机库、油井、桥梁、矿脉等科技建筑
  战役建筑/         # 战役关卡建筑（杰斐逊、克里姆林宫、自由女神像等）
  特殊单位/         # 天空骑士、磁暴坦克等
```

协议目录里的 `.webp` 在打包时转成 PNG 再编进 DLL。中立与战役建筑图标来自 [红警3 BWiki · 中立&战役建筑](https://wiki.biligame.com/redalert3/%E4%B8%AD%E7%AB%8B%26%E6%88%98%E5%BD%B9%E5%BB%BA%E7%AD%91)。叠加层按 PNG 文件名匹配场上单位显示名。界面上的种类名会转成简体；`unit_names.txt` 里的手写名优先。

新出现的种类追加在列表末尾，不会插进已有图标中间。

## 四、建造限制

侧栏 **建造限制**。上下两栏：上面是允许建造，下面是禁止建造。每栏按盟军、苏联、帝国分开展示图标，悬停显示名称。点允许栏里的图标即禁止，点禁止栏里的图标即恢复。

- 对当前对局里所有非中立玩家生效，包括 AI。名单会记住，进入下一局后自动再套一次，直到你手动解禁。
- 进局后会等战局时钟连续有效约 3 秒，才把禁止写进游戏。加载存档的那几秒里不去调游戏的建造接口，避免分配失败后读空指针。
- 车厂和船厂都能造的单位只显示一个图标（MCV、勘探者、激流 ACV、史普尼克勘察车、牛蛙载具、海啸坦克、采矿车 / 苏联矿车）。禁止后两边都不能造。

- 不收录开局就有的建造工厂，以及磁暴坦克、雷达碟、斩首中队、气球炸弹、点防御无人机、盟军前哨站、苏联战斗碉堡。
- 点某一座超级武器只限制这一座（纳米虫群核心会连同巢穴，超能波毁灭装置会连同它的核心）。开关「禁用超武」会把六座一起禁止：超时空传送仪、质子撞击炮、铁幕装置、真空内爆弹、纳米虫群核心、超能波毁灭装置。

## 六、技术原理

### 进程

`RA3.exe` 是启动器。真正的引擎是 `Data\ra3_1.12.game`。主模块无 ASLR，镜像基址 `0x400000`。`.text` / `.rdata` / `.data` 的文件偏移等于 RVA。

菜单画在 `Present` 上。`EndScene` 的钩子不负责画界面。渲染包在 SEH 里，避免一次绘制异常把游戏带走。

### MustCode

点「注入」后，DLL 调用同目录的 `arm_mustcode.dll`（内容仍是装配程序，扩展名做成 dll，避免和 `main.exe` 点错；内含 `keystone.dll`，用 `mustcode_asm.py` 装配），在游戏进程里分配几块内存并打 5 字节 `jmp`：

| 段 | 用途 |
|----|------|
| MustCode | 主要 hook 逻辑 |
| MustCode2 | 单位速度 / 血量 |
| FLAGS | 各功能开关，一字节一个 |
| IDB | 单位数据基址缓存 |

`.text` 默认只读，写补丁前会改页保护，写完再恢复。观战模式跳过 PlayerID、Money、Power、SCPoint、HaveAllSC。

17 个 hook（Steam 原版 1.12 VA）。起义时刻对应的 16 个地址见下面第九节：

| Hook | VA | 功能 |
|------|-----|------|
| PlayerID | `0x54119B` | 玩家 ID |
| Money | `0xA64E9E` | 金钱 |
| Power | `0xA64DAD` | 电力 |
| SCPoint | `0xA64F0C` | 科技点 |
| HaveAllSC | `0xA64F55` | 全科技 |
| FastBuild1 | `0x74D81E` | 快速建造 |
| FastBuild2 | `0x74D77C` | 快速建造 |
| FastBuild3 | `0x73511F` | 快速建造 |
| SuperPower | `0x729F19` | 超级武器 |
| SuperPower2 | `0x87CB89` | 超级武器 |
| DisableAllSP | `0x87CC16` | 禁用敌方超武 |
| DisableAllSP2 | `0x748A06` | 禁用敌方超武 |
| Map | `0x8005BC` | 消散战争迷雾 |
| UnitAmmo | `0x569D85` | 弹药无限 |
| DangerLevel | `0x877070` | 危险等级 |
| OreMine | `0x712EB3` | 恢复矿场 |
| EnemyCantBuild | `0x74D920` | 敌人无法建造 |

写入前会核对原始字节。对不上就报 probe failed：多半不是 1.12，或别的修改器已经改过这些位置。

### 另一层：MinHook

上面 17 个（起义时刻 16 个）MustCode hook 是自建 stub。摄像机、时间控制、动画 / Lua、杂项操作这四个面板另外用 MinHook 挂了几处，DLL 载入时由 `init()` 一次装好（`camera_install_hook` / `time_control_install` / `lua_bridge_install` / `misc_install`），装失败只会让对应面板显示「未就绪」，不影响 MustCode 那一层：

| 挂点 | 用途 |
|------|------|
| `0x821760` / `0x7EC240` / `0x7DC060` | 引擎设置相机矩阵与 View 初始化，见上面「摄像机接管」 |
| Lua C API 一组（`0x40A3F0` 起） | 捕获 `lua_State*`，见上面「Lua 桥」 |
| `CreateUnit` / `SpawnObject` / `Destroy` | 单位表快照（更早就装了，不是这四个面板新增的），供统计、建造限制、切换队伍的作用范围使用 |

每帧的推进统一挂在 Present 上：`drain_unit_spawns` → `camera_tick` → `time_control_tick` → `lua_bridge_tick` → `misc_tick` → 画界面。

### 选中单位

原版的速度、血量、摧毁、复制都从选中单位管理器出发：

```
[模块 + 0x8E08DC] = 管理器          绝对地址 0xCE08DC
管理器 +0x5C      = 当前选中数量
管理器 +0x50      = 选中链表头
  节点 +8         → 对象
  对象 +0x138     → 单位实体
  实体 +0x374     → 单位数据（+0x200 速度 / +0x33C 血量）
  实体 +0x3CC     → 经验追踪器
  实体 +0x418     → 归属玩家
```

`0x8E08DC` 是 RVA。函数地址（例如 `0x5173F0`、`0x6440F0`）是已经含基址的 VA。两者不能混用：把 RVA 再按 VA 去减 `0x400000`，会少整整一个基址，读到空列表。

Steam 版是重编译的二进制，零售版全局指针 `0x8DB73C` 在这份模块里没有引用。对象内部偏移 `+0x50 / +0x5C / +0x138` 没变。

### 玩家

玩家列表全局 RVA `0x8EDE2C`：

| 偏移 | 含义 |
|------|------|
| `+0x28` | 本地玩家 |
| `+0x2C` | 数量 |
| `+0x30` | `Player*[0x14]` |
| 玩家 `+0x14` | 显示名 |
| 玩家 `+0x20` | player_id，0 为中立 |
| 玩家 `+0x80 / +0x84` | 颜色 ARGB |
| 玩家 `+0xE4` | 资金 |
| 玩家 `+0x74` | 电力 |
| 玩家 `+0x1F0` | ScoreKeeper（累计，不是时间序列） |

资金加减写资金对象 `+0x04`，范围夹在 0 到 2 亿。

### 杂项操作 / 光照 / 阴影的地址

和 CameraBridge（零售版二进制）对比出来的三处全局。零售版全局偏移在这份重编译的模块里整体平移了：渲染对象与光照是 `+0x51A0`，阴影那一组是 `+0x5190`（两处之间 `.data` 有 0x10 的收缩）。已经按游戏自身的引用逐条核对过：

| 项 | Steam 1.12 绝对地址 | 偏移 | 校验依据 |
|----|--------------------|------|----------|
| 渲染对象指针 | `0x00CE08F0` | `+0x138` 单位剪影 / `+0x139` 血条维修 | `0xA32DE8` 画血条前 `mov eax,[0xCE08F0]; cmp byte [eax+0x139],0` |
| 光照配置指针 | `0x00CE0D78` | `+0x24` 才是光照结构 | `0x586800`、`0x61156D` 都走 `[[0xCE0D78]+0x24]` |
| 光照结构 |  | 环境光 `+00/04/08`、主光源 `+0C/10/14`、调色#1 `+30/34/38`、调色#2 `+54/58/5C` | `0x61156D` 用 `主光源*0.5 + 环境光` 再乘 255 得实际光色 |
| 阴影贴图大小 | `0x00CEEDB4` int | — | `0x93BBE6` 初始化成 `0x400`；`0x928A4F` 的 setter 写入可选档位 |
| 最大阴影距离 | `0x00CEEDB8` float | — | `0x93BBD8` 从常量 `1000.0` 初始化；与大小同属一个 setter 结构 |

`.data` 里这一片是未初始化段（文件里没有有效初值），所以只能靠游戏代码里的引用确认，不能靠静态初值。

### 摄像机接管（`camera.cpp`）

相机状态的真身是 `View+0x08` 的 3×4 矩阵；`+0x38 / +0x3C / +0x40 / +0x44` 只是缓存（X/Y/Z/朝向），`+0x260` 是相机距离。接管点选在引擎唯一的「设置相机矩阵」入口：

| 项 | 地址 | 说明 |
|----|------|------|
| `W3DView::setTransform` | `0x7EC240` | 签名 `__thiscall(const float* m)`，`ecx` = View。实测从不被调用 |
| 第二个 setTransform | `0x821760` | 同样的签名，实际跑的是这个，两个都挂 |
| `W3DView::Init` | `0x7DC060` | `CreateView`（`0x51A210`）建完对象立刻调用，`ecx` = View，每个 View 只调一次，用来第一时间拿到 View 指针 |
| View 登记表 | `0x00CEAAC0` | 槽位 = `0x00CEAAC0 + idx*16`，索引在 `0x00CEAA00`。hook 还没被调用过时从这张表兜底扫描 |
| View 主 vtable | `0x00C54BB0` | 构造 `0x7FFFE0` 写 `[this]`。派生链上还有 `0xC54D30 / 0xC54F60 / 0xC552A0 / 0xC55988 / 0xC55A60 / 0xC55AA0`，扫描时一并接受 |

`camera_apply` 写回前会检查 12 个矩阵分量都是有限浮点：一旦把 NaN/Inf 写进相机对象，游戏后续把它当指针或索引用就会崩溃。轨迹按「线性 / 贝塞尔 / 平滑样条」插值，播放推进和定时事件都在 Present 里走 `camera_tick()`。

### 游戏时间倍率（`time_control.cpp`）

全局指针 `0x00CE8138` 指向全局数据对象：

| 偏移 | 含义 |
|------|------|
| `+0x30` | GameSpeedFactor（只读展示，调试面板里就叫这个名字） |
| `+0x54` | 游戏时间倍率。0.6 最慢 / 1.0 正常 / 2.0 最快，**0 相当于暂停** |

设置函数（`0x6F9230` 一带）先把「0–100 的百分比」（50 = 正常）换算成倍率 —— `pct>50` 时 `scale = 1.0 + (pct-50)*0.02`，`pct<50` 时 `scale = 1.0 - (50-pct)*0.008` —— 再写 `[[0xCE8138]+0x54]`。所以改这 4 个字节就能控制整局速度。写前校验指针、当前值必须是有限浮点、目标倍率在 0–6 之间，任何一条不满足就拒绝并记日志，绝不盲写。

快进用同一个字段：把倍率拉到设定值，`present` 里读对局时钟，到了目标时间就把倍率写成 0 并清掉快进状态。

### Lua 桥（`lua_bridge.cpp`）

内嵌的是 SAGE/Corona 定制版 Lua 5.0。栈上一个值（TValue）16 字节，`+0x00` 是类型标签，`+0x08` 是 `double` / `GCObject*` / `int`；string 的字符数据在 `((TString*)value) + 0x14`。类型表由 `0x40A570`（lua_typename）从名字表 `0xBE2388` 读出：`0 = userdata / 1 = nil / 2 = number / 3 = string / 4 = table / 5 = function / 6 = lightuserdata`。

`lua_State` 里 `+0x00` 是 `top`、`+0x08` 是 `stack_last`、`+0x10` 是 `base`（一个槽 0x10 字节）。`lua_State*` 没有放在全局变量里（脚本对象的 `+0x24` 才是），所以用 MinHook 挂钩这几个 C API，从第一个参数捕获它：

| 地址 | 函数 |
|------|------|
| `0x40A3F0` | `lua_gettop(L)` |
| `0x40A540` | `lua_type(L, idx)` |
| `0x40A7B0` | `lua_tostring(L, idx)`（数字会就地转成字符串） |
| `0x40A8D0` / `0x40A930` / `0x40A9A0` | `lua_pushnil` / `lua_pushnumber` / `lua_pushstring` |
| `0x40AA70` / `0x40ACC0` | `lua_getglobal` / `lua_setglobal` |

写之前先校验 `top/base/stack_last` 都像合法指针、`top` 16 字节对齐；全程 `__try/__except` 兜底；读完把 `top` 还原成调用前的值（等价于弹栈），不依赖 `lua_settop` 在 `idx>=0` 时那条不确定的路径。

### 禁用游戏鼠标输入

没有挂钩子，直接吞消息：`hk_wndproc` 里判断一个原子标志，勾选时把 `WM_MOUSEFIRST..WM_MOUSELAST`、`WM_MOUSEWHEEL`、`WM_MOUSEHWHEEL` 全都 `return 0`，游戏收不到鼠标消息就不做悬停和点击判定，overlay 自己的窗口不受影响（ImGui 走的是自己那套输入）。

### 单位颜色字段

零售版 1.12 里单位颜色来自所属玩家对象（就是资金面板那些色块读的同一个字段）：玩家 `+0x80`（个别版本在 `+0x84`）是 `0x00RRGGBB`，高字节必须是 0。写前用这个形状校验，避免把指针误判成颜色后写坏玩家对象。原值在第一次改色前缓存，供「恢复原来的颜色」写回。所以这个功能是**按玩家整体换色**，不是单个单位。

### 满级为什么不在 hook 里调用游戏

`0x5173F0(entity, xp)` 是官方「给单位加经验」入口，内部会进 `ExperienceTrackerObject::SetRank`，由引擎自己派发晋升、EVA 和星星。直接写 `tracker+0x24` 只改缓存，游戏里的星级不变。

这个接口不能在 MustCode hook 里同步调用。玩家更新那条 hook 的调用者已经拿着全局锁 `0xCDDF20`，而加经验一进来又要加同一把非递归锁，会自死锁，游戏画面停住。现有 17 个 hook 都只做内存读写。满级、摧毁、复制、召唤基地车都放到独立线程里再 `call` 游戏函数。

经验追踪器（虚表邻近字符串 `ExperienceTrackerObject`）：

| 偏移 | 含义 |
|------|------|
| `+0x08` | 当前等级的定义键 |
| `+0x0C` | 当前经验（float） |
| `+0x10` | 下一级所需经验 |
| `+0x1C` | 经验倍率 |
| `+0x20` | 最低字节是「等级特效已播放」 |
| `+0x24` | 等级索引缓存，实测约 0–4。写入它不会让星星变化 |
| `+0x2C` | 加成对象 `sub` |
| `sub+0x08` | 当前加成倍率。伤害×5 写的是这里 |

### 出场等级和召唤

出场等级走生产老兵升级：`Upgrade_ProductionVeterancy_VETERAN / _ELITE / _HEROIC`，对应滑条 1 / 2 / 3。查找升级 `0x586CF0`，授予 `Player::setUpgrade` `0x88B800`，清除 `0x888510`。这是累加的，只影响之后生产的单位。

召唤基地车用 `CreateUnit` `0x6440F0`。模板从 Thing 工厂 RVA `0x008EBDE8` 按 `AlliedMCV` / `SovietMCV` / `JapanMCV` 查找，归属是基地车那一栏选中的玩家，落点是鼠标投影到地形的坐标。

### 加载战局时不要在游戏线程里分配

CreateUnit / SpawnObject / Destroy 的钩子只把指针放进固定数组，分类和建表放到界面线程。重扫单位表会等约 2.5 秒。建造限制要等战局时钟有效满 3 秒。加载存档时游戏自己的分配器可能返回空，紧接着读 `[NULL-4]`；如果钩子在同一条游戏线程上做堆分配，就会撞上这次崩溃。

崩溃日志记异常码、EBP 回溯，以及栈上能认出的模块偏移，写在 `ra3_overlay.log`。

### 换模式时的空指针

遭遇战结束后，玩家列表全局有时还指着已经释放的内存。脚本按座位取玩家时，读不到就当成没有这个玩家，继续往下走，不会把整张玩家表换成别的对象。AI 选择超武时，查找结果为空就跳过这一次。这两处在 DLL 载入时就装上。日志里应有 `ai power null guard`、`script player guard` 和 `player slot guard sites=2`。

### 存档里没有折线

遭遇战存档在「保存的游戏」目录下，例如：

```
C:\Users\<用户>\Saved Games\Red Alert 3\<档案号>\<名字>.RA3Skirmish
```

档案号来自 `%AppData%\Roaming\Red Alert 3\Profiles\directory.ini` 的 `CurrentProfile`。游戏用 `FOLDERID_SavedGames` 拼出这条路径。存档是 RGMH 头加 BLOK 块的快照（玩家、GameLogic、地图状态），里面没有逐秒统计。所以折线在开始记录之前只能从 0 直线连到当时的累计值。

## 七、编译

### 菜单 DLL

需要 VS Build Tools（x86）和 CMake：

```bat
cd overlay
build.bat
```

输出 `overlay\bin\ra3_overlay_v4.dll`。编完后重新运行注入器。

### 注入器

需要 Python、PyInstaller 和 keystone-engine：

```bat
cd overlay
build_injector.bat
```

脚本会先自动跑一遍 `build.bat` 把 DLL 编出来再打包（否则 `main.exe` 里会包着一份旧的 DLL，新加的界面在游戏里看不到）。已经单独编过 DLL、只想重打包时用 `build_injector.bat norebuild`。

注入器会把当时的 DLL、`arm_mustcode.dll`、名字表和图标打进去。

输出：

- `overlay\bin\main.exe`（管理员权限，发给别人只需要这一个文件）
- `overlay\bin\arm_mustcode.dll`（装配程序，扩展名是 dll，避免被当成要双击的程序；玩家那边由注入器自己释出）

若改过 `mustcode_body.asm` / `payload.py`，先在仓库根目录：

```bat
python gen_payload.py
```

Windows 安全中心有时会把注入器隔离。这是附加进程、写内存时的启发式误报。在「病毒和威胁防护 → 排除项」里加上本仓库目录或 `overlay\bin`，再从防护历史里还原文件。

## 八、排错

| 现象 | 可能原因 |
|------|----------|
| 注入弹窗写「注入失败」 | 先看正文：游戏没开、没管理员权限，或 DLL 被安全软件隔离 |
| 请关闭战网进程（RA3BattleNet） | 在线客户端还在运行。关掉 `Ra3.BattleNet.Client.exe` 和 `RA3BattleNet.exe` 后再开修改器 |
| 弹出两张 Steam 截图 | 当前进程不是 `ra3_1.12.game`。按图在启动选项填 `-runver 1.12` 后重开游戏 |
| 注入失败 / probe failed | 不是 1.12，或已有其它 MustCode 改写了对应字节 |
| 开关无效 | 未点「注入」；观战模式没装资源 hook，电力 / 科技点 / 全科技不会动 |
| 菜单「注入」失败找不到 arm | 注入器没把 `arm_mustcode.dll` 释到 DLL 旁边。重新运行注入器；若安全软件隔离了释出的文件，把该目录加进排除项 |
| arm 报 keystone 动态库失败 | 重新跑 `build_injector.bat`（需打包 `keystone.dll`） |
| 复制失败 | 鼠标不在地形上；先选中单位；观战时没有本地玩家归属 |
| 选中玩家资金没反应 | 还没进局，或列表里没点过玩家 |
| 菜单不出现 | Steam Overlay 冲突；看 log 是否有 `hooked Present` |
| 旧 DLL 占文件锁 | 关掉游戏后重编；输出名为 `ra3_overlay_v4.dll` |
| 加载战局后崩溃 | 看 `overlay\bin\ra3_overlay.log` 里的异常码和模块偏移，确认注入的是当前这份 DLL |
| 退出遭遇战，或接着进任务时崩溃 | 完全退出游戏后重新运行注入器。日志应有 `player slot guard sites=2`；若仍是 `player list read guard sites=7`，说明还在用上一份 DLL |
| 起义时刻弹「请把启动选项改成 -runver 1.0」 | 运行的起义时刻模块不是 `ra3ep1_1.0.game`，按弹窗里的两张图改启动选项后完全重启游戏 |
| 起义时刻某功能提示「暂未适配」 | 该功能依赖原版引擎函数地址，起义时刻没有对应落点，见第九节 |
| 摄像机页显示「hook 已就绪，等待游戏更新相机…」 | 还没进对局，或进局后没动过视角。移动一下镜头再回来 |
| 摄像机页显示「相机 hook 安装失败」 | 重新注入。多半是注入的那份 DLL 不是当前编出来的 |
| 时间控制 / 动画 Lua 显示「未读到」 | 只支持原版 1.12，且要进入对局。仍未读到就把 `ra3_overlay.log` 里 `time:` / `lua:` 开头的行发出来 |
| 改完单位颜色没变化 | 改的是玩家对象的颜色字段（`+0x80`），若游戏在造单位时就把颜色烘进渲染对象，则只有 UI 色块会变；数值变说明写入成功 |
| 切换队伍后单位被 AI 到处乱跑 | 生成时没勾「启用 AI 操控」。当前机制只是把速度写成 0 冻结，不是引擎级禁止 AI；用「恢复速度」解冻 |

只支持 Steam 原版 1.12 和起义时刻 1.0。其它版本的基址和原始字节对不上，注入会在 probe 处停住。

## 九、起义时刻（Uprising 1.0）

### 版本与引导

- 只适配 `ra3ep1_1.0.game`（起义时刻 1.0）。启动选项填 `-runver 1.0`。
- 若在跑起义时刻的其它版本（例如 `ra3ep1_1.1.game`），注入器不注入，改弹起义时刻专用的两张图，提示改成 `-runver 1.0`。
- 起义时刻**不做**原版那条严格版本校验：模块是 `ra3ep1_1.0.game` 就注入。原版校验仍只作用于 `ra3_1.12.game`。
- 起义时刻跳过针对零售二进制的引导补丁（观测者字节、空指针守卫等），只装起义时刻自己的 hook 表。

### hook 表（起义时刻 1.0 VA）

起义时刻是重新编译的二进制，多个结构体变大，同一字段往后挪。已适配的：

### 起义时刻的功能可用性

可用：

- **资源**：己方资金、选中玩家资金、电力无限、科技点无限、全科技、快速建造
- **超武 / 地图**：超级武器、禁用超武、消散战争迷雾、敌人无法建造、协议无冷却、单位技能无冷却、禁用敌方协议
- **弹药 / 危险**：弹药无限、危险等级
- **单位操作**：超速 / 慢速 / 冻结 / 恢复速度，无敌 / 残血 / 恢复血量
- **战况统计**：资金、电力，以及本局折线（建造 / 损失 / 消灭 / 收入 / 支出）

暂不可用（菜单会直接给「…暂未适配」「未找到游戏模块」的提示，不会静默失败，更不会去调用零售版地址）：

- 恢复矿场（起义时刻未装对应 hook）
- 复制、摧毁、满级、收编、伤害×5
- 召唤基地车、召唤部队
- 建造限制（起义时刻的建造接口未适配）
- 战况统计卡片上的部队 / 建筑 / 协议数量（起义时刻不做单位表扫描，只显示资金和电力）
- **摄像机**、**时间控制**、**动画 / Lua**、**杂项操作**四个面板（相机矩阵入口、时间倍率全局、Lua C API、渲染 / 光照 / 阴影全局都是原版地址）
- **单位操作扩展**：选择范围、切换队伍、切换颜色、禁用鼠标输入

### 已修的两个问题

**1）多出一行「玩家 己方 已击败」**

起义时刻在对局初始化之前，`ThePlayerList` 会先暴露一个未初始化的占位本地玩家（ID 0，没有资金对象）。战况面板一旦把它记进历史，零点几秒后被真正的本地玩家取代时，这个旧快照就从当前席位里消失了，于是被当成「已战败的席位」重新插回榜单。

修法：仅起义时刻启用占位判别（本地 + `player_id==0` + 没有资金对象），在录入、入场判断、战败回填和清理四条路径上都过滤，并做一次历史清洗。

**2）新造出来的单位自己往别处跑**

原版「消散战争迷雾」挂在 `0x8005BC`，改的是相机 / 视野对象里的 `[ebp+0x260]`（相机距离）。起义时刻同一个构造函数整体后移 4 字节，这条指令搬到 `0x80B9DF` 并写成 `[ebp+0x264]`；而零售版那条字节特征在起义时刻里匹配到了**构造函数内部**一个默认值 1.0 的字段。开关一开就把那个字段写成 100000.0，视野对象被写坏，屏幕↔世界坐标与集结点解算随之出错，表现就是新单位像被别的 AI 指挥一样跑向错误坐标。

修法：起义时刻的 Map hook 改用 `0x80B9DF` / 字节特征 `f30f118564020000`，stub 里也只改 `[ebp+0x264]`。两处替换长度不变，hook 段的偏移布局不受影响。

为排除同类隐患，本次逐个反汇编了两个版本的全部 stub，确认它们按原顺序重放了原始指令的助记符与操作数（原版 17 个 + 起义时刻 16 个，全部通过），因此起义时刻不存在第二处同类错位。
